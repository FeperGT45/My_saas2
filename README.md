# LingoRush

Основа SaaS-приложения для изучения языков в Telegram Mini App. Мобильный интерфейс на русском, расширяемая архитектура, без платных API. Текущий этап — игровой UI с локальными демоданными, без серверной авторизации и сохранения.

## Быстрый старт

Требуется Node.js 22.13+ (рекомендуется Node.js 24 LTS) и npm.

```bash
npm ci
cp .env.example .env.local
npm run dev
```

Откройте http://localhost:3000. Без переменных Supabase приложение также запускается. Локальный деморежим включается только при `NODE_ENV=development` и `NEXT_PUBLIC_ENABLE_LOCAL_DEMO=true`. Перезапустите сервер после изменения env. Не выставляйте dev-сервер в публичную сеть.

```bash
npm run lint
npm run typecheck
npm run format:check
npm run build
npm start
```

## Стек

Next.js App Router, React, TypeScript strict, Tailwind CSS 4, shadcn/ui (конфигурация и локальный Button на Radix/CVA), Motion, Lucide, Supabase JS, Telegram Mini Apps SDK (`@tma.js/sdk-react`). Версии зафиксированы в package-lock.json. Шрифты системные: сборка не зависит от загрузки Google Fonts.

## Структура

```text
src/app/                 маршруты, layout, состояния загрузки/ошибки
src/components/layout/   мобильная оболочка и навигация
src/components/ui/       переиспользуемые UI-компоненты
src/features/telegram/   клиентский provider и статус окружения
src/features/demo/       все локальные фикстуры, отдельно от будущего API
src/features/lesson/     интерактивный демоурок, состояние только в памяти
src/features/settings/   демонстрация переключателей настроек
src/lib/i18n/            словари и точка расширения локалей
src/lib/supabase/        необязательный клиент Supabase
src/config/              настройки окружения
```

Маршруты: `/` (главная), `/learn` (карта), `/courses` (каталог), `/lesson` (демоурок), `/leaderboard` (рейтинг), `/achievements`, `/profile`, `/settings`, `GET /api/health`. Дополнительно предусмотрены 404, loading и error boundary. Нижняя навигация учитывает safe-area; анимация учитывает reduced motion. Язык документа — `ru`; словари подключаются через `getDictionary`. Новые локали следует добавить в реестр и затем реализовать выбор/маршрутизацию локали. Сейчас доступен только русский интерфейс.

## Telegram и безопасность

Provider динамически загружает SDK после монтирования, определяет Telegram-окружение и вызывает mount/ready, когда они доступны. В обычном браузере показывается обзор, а в разрешённом dev-режиме — явная демоплашка. Ошибки SDK не блокируют обзор. Состояние `telegram` означает только наличие окружения, **не аутентификацию**.

Не реализованы вход и защищённые API. На следующем этапе сервер должен проверять Telegram `initData` с использованием bot token, ограничивать возраст `auth_date`, защищаться от повторного использования и выдавать серверную сессию. Нельзя доверять `initDataUnsafe`, данным пользователя из браузера или признаку dev-режима. Не передавайте bot token в клиент и не используйте demo для доступа к данным. Серверной точки входа, принимающей непроверенный Telegram payload, в каркасе нет.

Для ручной проверки внутри Telegram потребуется HTTPS-развёртывание/туннель и URL Mini App, настроенный через BotFather. Эта задача не создаёт бота и не публикует приложение.

## Supabase

`getSupabaseClient()` возвращает `null`, пока не заданы URL и publishable key. Клиент не используется для имитации записи данных; сессии в браузере пока не сохраняются. `NEXT_PUBLIC_*` публичны. `TELEGRAM_BOT_TOKEN` предназначен только для будущей серверной интеграции. Service-role ключи никогда не добавляйте в клиентские env.

Схема БД и миграции намеренно не создаются на этапе каркаса. Перед доступом к данным нужно определить схему, включить RLS на каждой таблице, написать политики и связать проверенную сервером Telegram-сессию с разрешённым механизмом авторизации Supabase. Publishable key сам по себе не является пользовательской авторизацией.

## Границы этапа

Восемь экранов в тёмной космической теме. Авторский маскот Ри — кристальный скат-комета, нарисованный SVG-компонентом `src/components/ui/mascot.tsx`, без внешних ассетов и персонажей. Объёмные кнопки, прогресс-бары, состояния загрузки/ошибки и пустые результаты поиска.

Демоурок состоит из трёх вопросов: выбор ответа, обратная связь, итог, повтор и выход. XP на итоговом экране условный и не меняет профиль/карту/рейтинг. Все игроки, прогресс, курсы и достижения — фикстуры в `src/features/demo/data.ts`; они не связаны с Supabase, Telegram-пользователем или будущим API. Каталог фильтруется по названию, вкладка друзей показывает пустое состояние. Переключатели настроек — явный UI-пример, не управляют устройством и не сохраняются. Системный reduced motion учитывается независимо.

Нет реального начисления XP, платежей, рейтингов, серверной авторизации и сохранения прогресса. Платные сервисы не подключены. Локальные демоэкраны доступны также в production как обзор; это не обход авторизации.

## Проверка интерфейса

```bash
npx playwright install chromium
npm run build
npm run test:ui
```

Playwright запускает production-сервер на порту 3001 (или использует уже запущенный вне CI). Проверяет все восемь экранов на ширинах 320, 390 и 768 px, отсутствие горизонтального переполнения и ошибок JavaScript, нижнюю навигацию, поиск и пустые состояния, правильный и неправильный ответ в уроке, итоговый результат, повтор, выход, переключатели/сброс настроек и 404. Telegram WebView требует отдельной проверки с реальным ботом и HTTPS; она не подменяется браузерными тестами.
