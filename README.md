# LingoRush

Основа SaaS-приложения для изучения языков в Telegram Mini App. Мобильный интерфейс на русском, расширяемая архитектура, без платных API. Текущий этап — игровой UI с локальными демоданными, без серверной авторизации и сохранения.

## Быстрый старт

Требуется Node.js 22.13+ (рекомендуется Node.js 24 LTS) и npm.

```bash
npm ci
cp .env.example .env.local
npm run dev
```

Откройте http://localhost:3000. Без переменных Supabase приложение также запускается. Локальный деморежим включается только при `NODE_ENV=development` и `NEXT_PUBLIC_ENABLE_LOCAL_DEMO=true`. Перезапустите сервер после изменения env. Не выставляйте dev-сервер в публичную сеть.

```bash
npm run lint
npm run typecheck
npm run format:check
npm run build
npm start
```

## Стек

Next.js App Router, React, TypeScript strict, Tailwind CSS 4, shadcn/ui (конфигурация и локальный Button на Radix/CVA), Motion, Lucide, Supabase JS, Telegram Mini Apps SDK (`@tma.js/sdk-react`). Версии зафиксированы в package-lock.json. Шрифты системные: сборка не зависит от загрузки Google Fonts.

## Структура

```text
src/app/                 маршруты, layout, состояния загрузки/ошибки
src/components/layout/   мобильная оболочка и навигация
src/components/ui/       переиспользуемые UI-компоненты
src/features/telegram/   клиентский provider и статус окружения
src/features/demo/       все локальные фикстуры, отдельно от будущего API
src/features/lesson/     интерактивный демоурок, состояние только в памяти
src/features/settings/   демонстрация переключателей настроек
src/lib/i18n/            словари и точка расширения локалей
src/lib/supabase/        необязательный клиент Supabase
src/config/              настройки окружения
```

Маршруты: `/` (главная), `/learn` (карта), `/courses` (каталог), `/lesson` (демоурок), `/leaderboard` (рейтинг), `/achievements`, `/profile`, `/settings`, `GET /api/health`. Дополнительно предусмотрены 404, loading и error boundary. Нижняя навигация учитывает safe-area; анимация учитывает reduced motion. Язык документа — `ru`; словари подключаются через `getDictionary`. Новые локали следует добавить в реестр и затем реализовать выбор/маршрутизацию локали. Сейчас доступен только русский интерфейс.

## Telegram и безопасность

Provider динамически загружает SDK после монтирования, определяет Telegram-окружение и вызывает mount/ready, когда они доступны. В обычном браузере показывается обзор, а в разрешённом dev-режиме — явная демоплашка. Ошибки SDK не блокируют обзор. Состояние `telegram` означает только наличие окружения, **не аутентификацию**.

Не реализованы вход и защищённые API. На следующем этапе сервер должен проверять Telegram `initData` с использованием bot token, ограничивать возраст `auth_date`, защищаться от повторного использования и выдавать серверную сессию. Нельзя доверять `initDataUnsafe`, данным пользователя из браузера или признаку dev-режима. Не передавайте bot token в клиент и не используйте demo для доступа к данным. Серверной точки входа, принимающей непроверенный Telegram payload, в каркасе нет.

Для ручной проверки внутри Telegram потребуется HTTPS-развёртывание/туннель и URL Mini App, настроенный через BotFather. Эта задача не создаёт бота и не публикует приложение.

## Supabase

`getSupabaseClient()` возвращает `null`, пока не заданы URL и publishable key. Клиент не используется для имитации записи данных; сессии в браузере пока не сохраняются. `NEXT_PUBLIC_*` публичны. `TELEGRAM_BOT_TOKEN` предназначен только для будущей серверной интеграции. Service-role ключи никогда не добавляйте в клиентские env.

Схема, RLS и миграции находятся в `supabase/`; инструкция ниже. Для работы с личными данными ещё потребуется связать проверенную сервером Telegram-сессию с Supabase Auth. Publishable key сам по себе не является пользовательской авторизацией.

## Границы этапа

Восемь экранов в тёмной космической теме. Авторский маскот Ри — кристальный скат-комета, нарисованный SVG-компонентом `src/components/ui/mascot.tsx`, без внешних ассетов и персонажей. Объёмные кнопки, прогресс-бары, состояния загрузки/ошибки и пустые результаты поиска.

Демоурок состоит из трёх вопросов: выбор ответа, обратная связь, итог, повтор и выход. XP на итоговом экране условный и не меняет профиль/карту/рейтинг. Все игроки, прогресс, курсы и достижения — фикстуры в `src/features/demo/data.ts`; они не связаны с Supabase, Telegram-пользователем или будущим API. Каталог фильтруется по названию, вкладка друзей показывает пустое состояние. Переключатели настроек — явный UI-пример, не управляют устройством и не сохраняются. Системный reduced motion учитывается независимо.

Нет реального начисления XP, платежей, рейтингов, серверной авторизации и сохранения прогресса. Платные сервисы не подключены. Локальные демоэкраны доступны также в production как обзор; это не обход авторизации.

## Проверка интерфейса

```bash
npx playwright install chromium
npm run build
npm run test:ui
```

Playwright запускает production-сервер на порту 3001 (или использует уже запущенный вне CI). Проверяет все восемь экранов на ширинах 320, 390 и 768 px, отсутствие горизонтального переполнения и ошибок JavaScript, нижнюю навигацию, поиск и пустые состояния, правильный и неправильный ответ в уроке, итоговый результат, повтор, выход, переключатели/сброс настроек и 404. ## PostgreSQL / Supabase

Миграции подготовлены для Supabase PostgreSQL 17. Удалённая база **не подключалась и не настраивалась**: в окружении нет Supabase credentials. Локальные проверки используют PGlite (PostgreSQL в WASM), подставляя только `auth.users`, `auth.uid()` и роли Supabase. Это проверяет SQL и RLS, но не заменяет интеграционную проверку Supabase Auth/PostgREST.

### Локальный запуск Supabase

Установите Supabase CLI и Docker по официальной документации. Из корня проекта:

```bash
supabase start
supabase db reset
supabase status
```

`db reset` удаляет локальные данные, применяет миграции по порядку и `supabase/seed.sql`. Seed содержит только публичный каталог и достижения; пользователей Auth, платежей и секретов там нет. Не используйте reset для базы с нужными данными. Скопируйте URL и publishable/anon key из локального Supabase в `.env.local` по `.env.example`. Секретный service-role key нужен только доверенным серверным jobs, не интерфейсу. Не коммитьте `.env.local`.

Для нового удалённого проекта сначала проверьте миграции на staging, затем выполните `supabase login`, `supabase link --project-ref <project-ref>`, проверьте `supabase db push --dry-run` и примените `supabase db push`. Эти команды здесь не выполнялись. Каталог можно загрузить отдельно через SQL Editor из `supabase/seed.sql` однократно. Не запускайте production seed с тестовыми пользователями.

### Модель и доступ

- `users.id` связан с `auth.users.id`; Telegram ID уникален, доступен только серверу. Регистрация профиля должна происходить доверенным сервером после будущей проверки Telegram и получения Supabase Auth identity. Автоматического создания профиля пока нет.
- Каталог: `languages → courses → units → lessons → exercises → exercise_options`. Позиции уникальны в родителе. Единственный поддерживаемый тип — `single_choice`: минимум два варианта и ровно один правильный ответ проверяются отложенными constraint triggers при commit. Редактируйте вопрос и варианты одной транзакцией.
- `user_progress` хранит завершённые уроки и лучший результат; `lesson_attempts` — попытки. `xp_events` — источник начисленного опыта, а не изменяемый счётчик на пользователе. Награда выдаётся один раз за урок, независимо от количества попыток.
- `daily_streaks` — уникальные дни активности в **UTC**, из которых в будущем вычисляется серия. `achievements` и `user_achievements` — каталог и награды; `referrals` запрещает самоприглашения и повторного приглашённого; `subscriptions` хранит интервалы и допускает не более одной активной записи на пользователя. Истёкшие статусы должен обновлять будущий доверенный job; одного `status=active` недостаточно для проверки доступа — учитывайте даты.
- На всех 15 таблицах включён RLS. `anon`/`authenticated` читают только активные языки и опубликованные курсы/уроки с проверкой всей цепочки родителей. Личные таблицы доступны только владельцу по `auth.uid()`, referrals — одному из двух участников. Публичного рейтинга с персональными данными пока нет.
- У браузера **нет INSERT/UPDATE/DELETE**. Нельзя менять XP, завершения, достижения, серии или подписки. Правильность вариантов (`is_correct`), объяснения заданий, Telegram ID и provider reference не выдаются клиенту: используются column grants, поэтому `select('*')` на таких таблицах запрещён. Запрашивайте только разрешённые столбцы.
- `award_completed_lesson(uuid)` доступна только `service_role`: блокирует завершённую попытку и атомарно обновляет XP, прогресс и UTC-день. Повторный вызов возвращает `false` без дублирования XP. Счёт и статус попытки должен вычислять будущий серверный grader, а не присылать браузер. Функция не проверяет ответы за grader. Общий HTTP endpoint или Server Action для этого намеренно не создаётся.

### Серверные методы

`src/lib/supabase/server.ts` помечен `server-only`: `getMyLearningSummary(token)` проверяет Supabase access token через `auth.getUser`, выводит identity из проверенного токена и использует RLS без service key. `getPublishedCourses()` возвращает ограниченную публичную проекцию. Клиенты создаются на запрос, сессии не разделяются и не сохраняются.

`src/lib/supabase/admin.ts` — только внутренний вызов RPC для будущего доверенного grader/job. Не экспортируйте его через общедоступный маршрут. Service key обходит RLS и требует отдельного контроля серверного вызова. Реальных подписок, webhook обработчиков и проверки Telegram на этом этапе нет. Демоинтерфейс продолжает использовать `features/demo`, не подключён к базе.

### Проверки базы без Docker и секретов

```bash
npm ci
npm run test:db
```

Тест поднимает изолированный in-memory PostgreSQL, применяет обе миграции и seed, проверяет RLS между двумя пользователями, сокрытие черновиков/ответов, запрет клиентских записей и RPC, FK/check/trigger ограничения и повторное начисление XP. Тестовые identity существуют только в памяти теста.
