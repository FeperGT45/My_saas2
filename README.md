# Voklumi

Основа SaaS-приложения для изучения языков в Telegram Mini App. Мобильный интерфейс на русском, расширяемая архитектура, без платных API. Текущий этап — игровой UI с локальными демоданными, с Telegram-авторизацией и без сохранения игрового прогресса.

## Быстрый старт

Требуется Node.js 22.13+ (рекомендуется Node.js 24 LTS) и npm.

```bash
npm ci
cp .env.example .env.local
npm run dev
```

Откройте http://localhost:3000. Без переменных Supabase приложение также запускается. Локальный деморежим включается только при `NODE_ENV=development` и `NEXT_PUBLIC_ENABLE_LOCAL_DEMO=true`. Перезапустите сервер после изменения env. Не выставляйте dev-сервер в публичную сеть.

```bash
npm run lint
npm run typecheck
npm run format:check
npm run build
npm start
```

## Стек

Next.js App Router, React, TypeScript strict, Tailwind CSS 4, shadcn/ui (конфигурация и локальный Button на Radix/CVA), Motion, Lucide, Supabase JS, Telegram Mini Apps SDK (`@tma.js/sdk-react`). Версии зафиксированы в package-lock.json. Шрифты системные: сборка не зависит от загрузки Google Fonts.

## Структура

```text
src/app/                 маршруты, layout, состояния загрузки/ошибки
src/components/layout/   мобильная оболочка и навигация
src/components/ui/       переиспользуемые UI-компоненты
src/features/telegram/   клиентский provider и статус окружения
src/features/demo/       все локальные фикстуры, отдельно от будущего API
src/features/lesson/     интерактивный демоурок, состояние только в памяти
src/features/settings/   демонстрация переключателей настроек
src/lib/i18n/            словари и точка расширения локалей
src/lib/supabase/        необязательный клиент Supabase
src/config/              настройки окружения
```

Маршруты: `/` (главная), `/learn` (карта), `/courses` (каталог), `/lesson` (демоурок), `/leaderboard` (рейтинг), `/achievements`, `/profile`, `/settings`, `GET /api/health`. Дополнительно предусмотрены 404, loading и error boundary. Нижняя навигация учитывает safe-area; анимация учитывает reduced motion. Язык документа — `ru`; словари подключаются через `getDictionary`. Новые локали следует добавить в реестр и затем реализовать выбор/маршрутизацию локали. Сейчас доступен только русский интерфейс.

## Telegram и безопасность

SDK инициализируется только в браузере: mount/ready, расширение viewport, CSS-переменные safe-area. Back Button скрыта на главной, на уроке ведёт к карте, из настроек/достижений — в профиль, с остальных экранов — на главную. Используются доступные методы SDK, есть браузерный fallback.

`POST /api/auth/telegram` принимает **только** `initData`. Сервер проверяет HMAC-SHA256 по bot token с constant-time сравнением, запрещает дубли ключей и некорректный hash, ограничивает размер тела, проверяет auth_date (не старше 5 минут, не более 30 секунд в будущем) и форму пользователя. Telegram ID, имя, username и HTTPS URL аватара извлекаются только после проверки подписи. `initDataUnsafe` не используется для доверенных данных.

В Supabase создаётся отдельная внутренняя Auth identity без доступного пользователю пароля и профиль `users`; атомарная RPC сохраняет профиль и серверную сессию. Сессия — случайный 256-битный токен в HttpOnly SameSite=Lax cookie (Secure и __Host-prefix в production), в БД хранится только SHA-256 токена. Срок — сутки, без автоматического продления. Подписанный initData hash уникален: повтор без действующей сессии отклоняется. Повторный запрос из уже авторизованного браузера допускается после повторной проверки подписи и совпадения identity.

`GET /api/auth/session` — защищённая точка чтения собственного аккаунта (401 без сессии); профиль отображается над демонстрационной статистикой. `POST /api/auth/logout` удаляет запись сессии и cookie. Auth POST-запросы проверяют Origin по `APP_URL`; ответы аккаунта не кэшируются. Сессия Telegram не является Supabase JWT: браузеру не выдаются service key или привилегии RLS. Для будущих защищённых маршрутов вызывайте `getSessionUser(request)` и выбирайте данные **только** по возвращённому user ID. Не используйте присланный клиентом ID и не передавайте произвольные запросы в adminClient.

Инициализация Telegram и успешная серверная авторизация — разные состояния. При ошибке входа интерфейс остаётся доступен как явное демо. Демо XP и игровой прогресс не сохраняются. Реальный вход требует миграции 003 и Supabase service key; без них endpoint возвращает 503, не подменяя вход тестовой учётной записью.

## Supabase

`getSupabaseClient()` возвращает `null`, пока не заданы URL и publishable key. Клиент не используется для имитации записи данных; сессии в браузере пока не сохраняются. `NEXT_PUBLIC_*` публичны. `TELEGRAM_BOT_TOKEN` предназначен только для будущей серверной интеграции. Service-role ключи никогда не добавляйте в клиентские env.

Схема, RLS и миграции находятся в `supabase/`; инструкция ниже. Для работы с личными данными ещё потребуется связать проверенную сервером Telegram-сессию с Supabase Auth. Publishable key сам по себе не является пользовательской авторизацией.

## Границы этапа

Восемь экранов в тёмной космической теме. Авторский маскот Ри — кристальный скат-комета, нарисованный SVG-компонентом `src/components/ui/mascot.tsx`, без внешних ассетов и персонажей. Объёмные кнопки, прогресс-бары, состояния загрузки/ошибки и пустые результаты поиска.

Демоурок состоит из трёх вопросов: выбор ответа, обратная связь, итог, повтор и выход. XP на итоговом экране условный и не меняет профиль/карту/рейтинг. Все игроки, прогресс, курсы и достижения — фикстуры в `src/features/demo/data.ts`; они не связаны с Supabase, Telegram-пользователем или будущим API. Каталог фильтруется по названию, вкладка друзей показывает пустое состояние. Переключатели настроек — явный UI-пример, не управляют устройством и не сохраняются. Системный reduced motion учитывается независимо.

Нет реального начисления XP, платежей, рейтингов и сохранения игрового прогресса. Платные сервисы не подключены. Локальные демоэкраны доступны также в production как обзор; это не обход авторизации.


Playwright запускает production-сервер на порту 3001 (или использует уже запущенный вне CI). Проверяет все восемь экранов на ширинах 320, 390 и 768 px, отсутствие горизонтального переполнения и ошибок JavaScript, нижнюю навигацию, поиск и пустые состояния, правильный и неправильный ответ в уроке, итоговый результат, повтор, выход, переключатели/сброс настроек и 404. ## PostgreSQL / Supabase

Миграции подготовлены для Supabase PostgreSQL 17. Удалённая база **не подключалась и не настраивалась**: в окружении нет Supabase credentials. Локальные проверки используют PGlite (PostgreSQL в WASM), подставляя только `auth.users`, `auth.uid()` и роли Supabase. Это проверяет SQL и RLS, но не заменяет интеграционную проверку Supabase Auth/PostgREST.

### Локальный запуск Supabase

Установите Supabase CLI и Docker по официальной документации. Из корня проекта:

```bash
supabase start
supabase db reset
supabase status
```

`db reset` удаляет локальные данные, применяет миграции по порядку и `supabase/seed.sql`. Seed содержит только публичный каталог и достижения; пользователей Auth, платежей и секретов там нет. Не используйте reset для базы с нужными данными. Скопируйте URL и publishable/anon key из локального Supabase в `.env.local` по `.env.example`. Секретный service-role key нужен только доверенным серверным jobs, не интерфейсу. Не коммитьте `.env.local`.

Для нового удалённого проекта сначала проверьте миграции на staging, затем выполните `supabase login`, `supabase link --project-ref <project-ref>`, проверьте `supabase db push --dry-run` и примените `supabase db push`. Эти команды здесь не выполнялись. Каталог можно загрузить отдельно через SQL Editor из `supabase/seed.sql` однократно. Не запускайте production seed с тестовыми пользователями.

### Модель и доступ

- `users.id` связан с `auth.users.id`; Telegram ID уникален, доступен только серверу. Регистрация профиля должна происходить доверенным сервером после будущей проверки Telegram и получения Supabase Auth identity. После проверки initData сервер создаёт профиль и сессию.
- Каталог: `languages → courses → units → lessons → exercises → exercise_options`. Позиции уникальны в родителе. Единственный поддерживаемый тип — `single_choice`: минимум два варианта и ровно один правильный ответ проверяются отложенными constraint triggers при commit. Редактируйте вопрос и варианты одной транзакцией.
- `user_progress` хранит завершённые уроки и лучший результат; `lesson_attempts` — попытки. `xp_events` — источник начисленного опыта, а не изменяемый счётчик на пользователе. Награда выдаётся один раз за урок, независимо от количества попыток.
- `daily_streaks` — уникальные дни активности в **UTC**, из которых в будущем вычисляется серия. `achievements` и `user_achievements` — каталог и награды; `referrals` запрещает самоприглашения и повторного приглашённого; `subscriptions` хранит интервалы и допускает не более одной активной записи на пользователя. Истёкшие статусы должен обновлять будущий доверенный job; одного `status=active` недостаточно для проверки доступа — учитывайте даты.
- На всех 15 таблицах включён RLS. `anon`/`authenticated` читают только активные языки и опубликованные курсы/уроки с проверкой всей цепочки родителей. Личные таблицы доступны только владельцу по `auth.uid()`, referrals — одному из двух участников. Публичного рейтинга с персональными данными пока нет.
- У браузера **нет INSERT/UPDATE/DELETE**. Нельзя менять XP, завершения, достижения, серии или подписки. Правильность вариантов (`is_correct`), объяснения заданий, Telegram ID и provider reference не выдаются клиенту: используются column grants, поэтому `select('*')` на таких таблицах запрещён. Запрашивайте только разрешённые столбцы.
- `award_completed_lesson(uuid)` доступна только `service_role`: блокирует завершённую попытку и атомарно обновляет XP, прогресс и UTC-день. Повторный вызов возвращает `false` без дублирования XP. Счёт и статус попытки должен вычислять будущий серверный grader, а не присылать браузер. Функция не проверяет ответы за grader. Общий HTTP endpoint или Server Action для этого намеренно не создаётся.

### Серверные методы

`src/lib/supabase/server.ts` помечен `server-only`: `getMyLearningSummary(token)` проверяет Supabase access token через `auth.getUser`, выводит identity из проверенного токена и использует RLS без service key. `getPublishedCourses()` возвращает ограниченную публичную проекцию. Клиенты создаются на запрос, сессии не разделяются и не сохраняются.

`src/lib/supabase/admin.ts` — только внутренний вызов RPC для будущего доверенного grader/job. Не экспортируйте его через общедоступный маршрут. Service key обходит RLS и требует отдельного контроля серверного вызова. Платёжных webhook и реальных подписок нет; Telegram webhook и проверка initData описаны выше. Демоинтерфейс продолжает использовать `features/demo`, не подключён к базе.

### Проверки базы без Docker и секретов

```bash
npm ci
npm run test:db
```

Тест поднимает изолированный in-memory PostgreSQL, применяет все миграции и seed, проверяет RLS между двумя пользователями, сокрытие черновиков/ответов, запрет клиентских записей и RPC, FK/check/trigger ограничения и повторное начисление XP. Тестовые identity существуют только в памяти теста.

## Подключение бота @Voklumi_bot

Bot API подтвердил username `Voklumi_bot` для предоставленного токена. Имя Voklumi и команда `/start` уже установлены через Bot API; webhook и кнопка пока не активированы. Код проекта обрабатывает `/start`. Для нового бота используйте `/newbot`, для существующего — его токен. Токен из переписки **не записывался** в файлы проекта, Git или клиентский код. Введите его самостоятельно в секреты хостинга либо в игнорируемый `.env.local`.

1. Разместите Next.js на HTTPS-домене, задайте канонический `APP_URL=https://your-domain.example` (без пути) и Supabase env. Примените миграции, включая `202611020003_telegram.sql`.
2. Задайте `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME=Voklumi_bot` и случайный `TELEGRAM_WEBHOOK_SECRET` (32+ символов, допустимы a-z/A-Z/0-9/_/-). Это три разные настройки; секрет webhook не равен bot token.
3. В BotFather настройте `/setdomain` и Mini App через `/newapp` или настройки бота с тем же HTTPS URL. Для прямой Mini App ссылки может потребоваться отдельный short name; username бота не является доменом приложения.
4. После настройки production env выполните `npm run telegram:setup` из окружения с `.env.local`. Скрипт использует env, задаёт имя Voklumi, команду `/start`, кнопку меню и webhook `/api/telegram/webhook`. Скрипт **не запускался** здесь: публичный HTTPS URL не предоставлен.
5. Напишите боту `/start` в приватном чате. Он отправит кнопку `web_app` «Открыть Voklumi». Webhook проверяет секретный заголовок Telegram, ограничения размера и тип чата; ошибки Bot API не раскрывают токен. Доставка Telegram — at-least-once: при редком повторе update возможно повторное приветствие, финансовых операций здесь нет.

Имя Voklumi_bot само по себе не позволяет настроить webhook. Удалённая Supabase, production webhook, кнопка и реальный мобильный Telegram не проверялись. Локальные тесты не заменяют проверку входа и Back Button на Android/iOS после размещения.

Сессии `telegram_sessions` закрыты RLS и доступны только серверу. По расписанию удаляйте истёкшие записи; уникальные hash можно удалять после истечения сессии (срок initData уже истёк). Не логируйте initData, cookies, bot API URL с токеном или service key. На хостинге настройте лимиты запросов к auth/webhook на уровне reverse proxy. Если сервер завершится между созданием Auth identity и RPC, может остаться неиспользуемая случайная Auth identity: удаляйте такие orphan-записи отдельной обслуживающей задачей. Существующие Auth identities никогда не удаляются при ошибке повторного входа.

## Безопасная локальная авторизация

Не связана с `NEXT_PUBLIC_ENABLE_LOCAL_DEMO`. Для тестовой сессии нужны одновременно `NODE_ENV=development`, loopback hostname, `ENABLE_LOCAL_AUTH=true`, `LOCAL_AUTH_SECRET` длиной не менее 32 символов и совпадающий Origin. Секрет не должен иметь префикс NEXT_PUBLIC_.

Запустите `npm run dev`, затем отправьте локальный POST `/api/auth/local` с заголовками `Origin: http://localhost:3000` и `X-Local-Auth-Secret: <ваш локальный секрет>` (например, через DevTools или REST-клиент). Ответ выставит отдельную подписанную cookie на час. Она создаёт только identity `local-demo` в памяти ответа, не пишет в Supabase и никогда не принимается в production. Не используйте локальный секрет в общем туннеле. Выход — `/api/auth/logout` с тем же Origin.

Проверки: `npm run test:auth` (подпись, подмена, срок, пользователь, Origin, изоляция dev), `npm run test:db` (профиль, сессия, защита от replay и RLS), `npm run build && npm run test:ui` (интерфейс и production-маршруты авторизации).
