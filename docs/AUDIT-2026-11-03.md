# Аудит Voklumi (ранее LingoRush) · 3 ноября 2026

Аудит существующего приложения; интерфейс и рабочие функции сохранены. Проверки выполнены на Next.js 16.4.3 и локальном Cloudflare workerd/vinext 1.4.1. Результаты локальных тестов не заменяют проверку на настоящем устройстве Telegram.

## Удалённые проверки и ограничения

Supabase доступен через подключённый сервис. Read-only readiness подтверждает схему `202611020010`, 22 таблицы, protectedColumns и rpcPermissions. После применения двух индексов readiness остаётся true. Миграция не меняет оплаченные периоды, награды или профили. Клиентские тесты в основном используют изолированную PGlite и подмену транспорта; отдельный admin fixture запускает настоящий Next.js с HttpOnly cookie и локальным HTTPS PostgREST-адаптером. Тесты не отключают production-авторизацию в коде приложения.

Остаются известные ограничения:

- Главная, каталог и карта всё ещё содержат явно обозначенную демо-оболочку. Подключение этих экранов к полноценному каталогу — отдельная продуктовая работа, не скрытая под прохождением тестов аудита.
- Реальный мобильный Telegram WebView, Safari, полный цикл Stars, длительные холодные старты и одновременные транзакции нескольких настоящих PostgreSQL-соединений не проверялись. Реальные платежи остаются выключены.
- Полный `npm audit` показывает 16 moderate предупреждений dev-инструментов ESLint/minimatch. Исправленная upstream major minimatch 11 несовместима с рядом используемых API старых веток; принудительная подмена не выполнялась. В runtime production-зависимостях предупреждений нет. [Advisory](https://github.com/advisories/GHSA-g3hv-75wg-m249).
- Не проведена нагрузочная проверка / защита распределённым rate limit. Уникальные награды и ограничение открытых попыток предотвращают повторную выдачу XP; это не обещание защиты от любого автоматизированного трафика.
- Supabase Advisor: RLS без клиентских политик на закрытых таблицах — ожидаемый deny-by-default; helper `current_user_has_premium()` проверяет только собственный auth.uid(), а не произвольный ID. [Разбор SECURITY DEFINER](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable).
- Проверка утёкших паролей Supabase выключена; приложение не предоставляет парольного входа. Настройка Auth не изменялась в этом аудите. [Настройка проверки](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).
- Performance Advisor сохраняет INFO по составному FK xp_events: уникальный индекс attempt_id уже ограничивает соответствующую проверку одной строкой. Новый дублирующий индекс не нужен. Неиспользуемые индексы на новом проекте не удалялись: часть обеспечивает уникальность/будущие выборки. [Пояснение проверки FK](https://supabase.com/docs/guides/database/database-linter?lint=0001_unindexed_foreign_keys).
