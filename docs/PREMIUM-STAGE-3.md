# Этап 3: аналитика английского

Экран `/analytics`, доступный из профиля и Premium. Подробный отчёт требует `advanced_statistics`. Базовый профиль, прогресс, XP и бесплатные рекомендации не меняются. Этап заканчивается коммитом, без автоматической публикации интерфейса в Cloudflare.

## Источники и ограничения

Только реальные завершённые попытки английских уроков (`lesson_attempts`), сохранённые снимки типов упражнений (`lesson_attempt_items`) и проверенные ответы (`exercise_submissions`). Повторы и неудачные завершённые попытки учитываются отдельно. Незавершённые/брошенные попытки, тест определения уровня и уроки других языков исключены. Старые завершённые попытки без сохранённых ответов остаются в истории и времени, но не создают выдуманный процент.

Единица точности — проверенное упражнение, а не отдельный подпункт комплексного задания. Процент взвешивается по количеству заданий, а не усредняет проценты уроков. Тема — тема урока с названием курса и раздела. Без автоматического угадывания грамматического правила.

Навык определяется по сохранённому типу упражнения:

| Навык       | Типы                                                                         |
| ----------- | ---------------------------------------------------------------------------- |
| Грамматика  | grammar, gap, sentence, word_order, error_identification, correction, tenses |
| Лексика     | translation, matching, spelling, synonym_antonym, word_review                |
| Чтение      | reading, dialogue                                                            |
| Аудирование | listening, dictation                                                         |

Упражнения с неоднозначным основным навыком, включая универсальный single_choice и комплексный unit_test, считаются «без однозначного навыка». Их количество показано; они входят в общую точность и темы. Это прозрачная классификация по формату задания, а не доказательство владения навыком.

Период — последние 7, 30 или 90 календарных дней, включая текущий, в часовом поясе профиля. Предыдущий период имеет ту же длину и непосредственно предшествует выбранному. Текущий день неполный. Дневные результаты относятся к дню завершения попытки, а не к времени ввода каждого ответа. Отсутствие ответов — `null` и разрыв линии графика, а не 0%.

Сравнение точности показывается в процентных пунктах только при наличии хотя бы пяти заданий в каждом периоде. Более мелкие выборки всё равно имеют свой честный процент и размер, но помечаются как малые. Это порог отображения, не статистическая значимость. Сложность и темы могли меняться; сравнение не доказывает причинный эффект обучения. Наиболее сложные темы: минимум пять заданий и точность ниже 60%, максимум пять тем. Недостаток таких тем не объявляется полным освоением.

Время — сохранённый интервал от открытия до завершения, включая паузы и фон. Отчёт не называет его активным учебным временем. Показаны сумма, среднее, медиана, сравнение с предыдущим периодом и число попыток дольше двух часов. Длинные интервалы не обрезаются и не подменяются предполагаемым временем. Пустые значения остаются `null`.

Ни проценты, ни сравнения не выдаются за официальную CEFR-сертификацию. Рекомендации объединяют доступные слабые темы отчёта и существующий подбор следующего урока по предварительному уровню, цели и прогрессу. В API не возвращается внутренний учебный контекст. Проверка доступа при открытии самого урока остаётся в существующем движке.

## Сервер и производительность

`GET /api/analytics?days=30&offset=0` принимает только период и смещение истории. Идентификатор пользователя извлекается из проверенной Telegram-сессии. Неизвестные/повторные параметры и недопустимые периоды отклоняются. `Cache-Control: no-store`. Ответы упражнений, ключи проверки, обратная связь с ответами и служебные ключи клиенту не передаются.

API проверяет `advanced_statistics`; RPC `english_analytics(uuid,integer,integer)` повторно проверяет право по актуальной базе. Клиентские роли не имеют `EXECUTE`. Функции работают как `SECURITY INVOKER` с фиксированным `search_path`, вызываются серверным клиентом. Подмена Premium или чужого userId в браузере не предоставляет доступа. При истечении Premium данные не удаляются, а API закрывается; UI перепроверяет доступ при фокусе и раз в минуту.

Один RPC агрегирует выбранный и предыдущий периоды в одном согласованном снимке данных. Материализованные CTE повторно используют ограниченный по пользователю и времени набор попыток и проверенных упражнений. Максимальное окно — 180 календарных дней. Используются существующий частичный `learning_recent_completed_idx(user_id,completed_at DESC,id)` и первичные ключи `(attempt_id,position)`; дублирующий индекс и отдельная таблица событий аналитики не создаются. История возвращается по 20 записей со стабильной сортировкой времени и id; смещение ограничено 100000. Темы агрегируются по урокам выбранного периода, а экран раскрывает их постепенно.

`english_analytics_database_status` и `npm run analytics:check` проверяют версию, индекс и закрытые права RPC. Эта проверка включена в production preflight, чтобы интерфейс не выпускался без готовой базы.

## Проверки и выпуск

Миграция создаётся штатным `supabase migration new english_analytics`, затем проверяется на изолированной PostgreSQL-базе до применения. Реальные пользовательские данные для тестов не меняются; Premium выдаётся только тестовым идентичностям в изолированной базе.

`tests/unit/analytics.test.ts`: пустые состояния, все периоды, взвешенные проценты, навыки и неоднозначные типы, предыдущие результаты, время, границы, другие языки/пользователи, незавершённые попытки, ретейки, пагинация, часовой пояс, права, окончание/возобновление Premium, отсутствие секретного содержимого и разрывы графика.

`tests/analytics.spec.ts`: настоящий Next API и изолированная PostgreSQL, Free/Premium, пустой/заполненный отчёт, смена периода, размеры 320 px, доступность графика и таблицы, отсутствие внутреннего контекста в ответе, смена пользователя и закрытие после окончания подписки. Отдельная проверка входного экрана и анонимного API доступна для Next/Worker.

Миграция `20261104104044_english_analytics.sql` применена к Supabase `wpctwlgfnkekgulgkxad`; readiness вернул `analytics-v1 / ready: true`. Существующие ответы, прогресс и подписки не изменялись. Новых предупреждений безопасности после применения нет. Сохраняются прежние INFO закрытых RLS-таблиц и предупреждения старого helper для RLS ([anon](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable), [authenticated](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable)) и [защиты паролей](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection). Новые функции — invoker, а не definer.

Прошли 148 unit-тестов в 12 файлах, 11 production preflight тестов и 5 браузерных сценариев на Next.js (аналитика, бесплатный прогресс и серверные права Premium). Сборка Next.js прошла с увеличенным локальным лимитом памяти для проверки типов. ESLint и Prettier — без ошибок. Cloudflare/Vite production build успешен. Дополнительно прошла проверка входного экрана и отказа анонимному API на локальном Worker. Авторизованный отчёт тестируется на настоящем Next API с изолированной PostgreSQL, а не на рабочем аккаунте; production-секреты в локальный Worker не переносились. Известные предупреждения сборщика об оптимизации lucide-imports и sourcemap плагинов остаются и не останавливают сборку.

В старом блоке Premium удалён неоднозначный процент при отсутствии ответов: точность теперь предлагается смотреть в подробном отчёте с корректными пустыми состояниями. Скриншоты на тестовых данных: `artifacts/premium-stage3/report.png` и `artifacts/premium-stage3/graph.png`. Реальные платежи и AI API не добавляются.
