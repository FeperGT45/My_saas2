# Voklumi: настройки устройства и подготовка запуска, 16 ноября 2026

По запросу владельца выполнены работы по платёжной проверке, настройкам интерфейса и расширению проверок. Резервные копии, независимая редактура уроков и аудиоматериалы в эту поставку не входят.

## Рабочие настройки

Виброотклик и эффекты больше не являются демонстрационными переключателями. Настройки хранятся локально в `voklumi.experience.v1`, восстанавливаются после перезагрузки и синхронизируются между вкладками. Сброс возвращает значения по умолчанию. Ошибки/запрет localStorage не останавливают приложение; в таком случае настройки действуют только в текущей вкладке. Они относятся к устройству и браузеру, а не к аккаунту Supabase.

Виброотклик по умолчанию выключен. После инициализации Telegram SDK используются проверяемые на доступность `hapticFeedback.impactOccurred('light')` для нажатий и `notificationOccurred` для подтверждённых результатов упражнений. При выключенном звуке виброотклик работает независимо. Скрытая вкладка, неподдерживаемый клиент, удалённый SDK bridge и исключение клиента не вызывают сбой. Частые нажатия ограничены одним откликом за 80 мс. Физическое ощущение вибрации требует проверки в настоящем клиенте Telegram на устройстве с поддержкой.

Отключение эффектов применяется к CSS-анимациям, переходам и Motion-компонентам уроков, карты, маршрута, теста, наград и челленджей. Системное уменьшение движения имеет приоритет, даже когда переключатель эффектов включён. Звук и озвучка сохраняют прежнюю реализацию.

## Stars

Сверены официальные требования Telegram: цифровые услуги оплачиваются XTR; тестирование выполняется на отдельном Test Server; возврат — `refundStarPayment`. Рабочий бот и production-токен для теста не используются. Источники: [Stars](https://core.telegram.org/bots/payments-stars), [Test Environment](https://core.telegram.org/bots/features#dedicated-test-environment), [HapticFeedback](https://core.telegram.org/bots/webapps#hapticfeedback).

Пять Node-тестов и SQL-сценарий платежей прошли, включая плательщика/валюту/сумму, срок, повторные уведомления, атомарность, возвраты и отзыв доступа. `npm run test:stars-official -- --prepare` успешно создал изолированную схему. Это **не официальная покупка**. Владелец подтвердил отсутствие отдельного тестового бота; `TELEGRAM_TEST_BOT_TOKEN` в окружении отсутствует. Официальная покупка и возврат остаются заблокированными до предоставления тестового подключения и действий владельца в Test DC.

Дальнейшие шаги владельца описаны в [STARS-OFFICIAL-TEST.md](STARS-OFFICIAL-TEST.md). На любом ПК используется файл `.env.stars-test.local` в корне существующего репозитория, а не фиксированный путь диска из старого отчёта. Токен не отправлять в переписку. Требуется подтвердить два тестовых счёта; настоящий платёж не нужен. Production-флаги оплаты, ручной проверки владельцем и возвратов остаются `false`.

## Нагрузка

Добавлена `npm run release:load`: только публичное чтение `/api/library`, 24 запроса на каждом уровне параллельности 1/4/8. При ошибке или ограничении запросов следующая ступень не запускается. Нет пользовательской сессии, создания аккаунтов, изменения данных или платежей. `RELEASE_APP_URL` позволяет направить проверку на отдельный HTTPS-стенд.

Дополнительный режим `npm run release:load -- --soak` после трёх ступеней выполняет до 480 чтений с параллельностью 8, паузой 500 мс между запросами каждого клиента и пределом 60 секунд. Он также останавливается при ошибке. Это ограниченная продолжительная проверка, без попытки исчерпать бесплатные квоты.

Проверка опубликованного Worker 16 ноября: все 72 чтения успешны, каталог содержит 301 опубликованный материал. p95 по ступеням: 796/711/825 мс, максимумы 1049/939/831 мс. Проверяются структура и отсутствие известных ключей ответов в публичном JSON. Это ограниченный smoke/load, а не максимальная ёмкость бесплатного Worker и не нагрузка множества авторизованных учеников. Для большого стресс-теста нужен отдельный стенд с реалистичными аккаунтами, лимитами и наблюдением за квотами; рабочая база такими аккаунтами не заполнялась.

Повторная проверка с `--soak` прошла: 552 успешных чтения, включая 480 за 58,9 секунды на последней ступени. Для этой ступени p50 — 459 мс, p95 — 613 мс, максимум — 882 мс; ошибок и rate limit не наблюдалось. Это не проверка авторизованного прохождения уроков под нагрузкой.

## Повторяемые проверки

```bash
npm ci
npx playwright install --with-deps chromium firefox webkit
npm run lint
npm run typecheck
npm run test:unit -- --maxWorkers=2
npm run test:regression
npm run build
npm run test:devices
npm run build:cloudflare
npm run check:cloudflare
npm run test:stars-official -- --prepare
npm run release:load
```

`test:devices` использует Chromium с профилем Pixel 7, WebKit с профилем iPhone 13, Firefox и альбомный профиль Android. Проверяются все 23 экрана на 320/390/768 px, навигация, реальный размер профиля и поворот, сохранение/сброс настроек, синхронизация вкладок и системное уменьшение движения. Эмуляция не является проверкой настоящих Android/iOS, аппаратного виброотклика или Telegram WebView.

## Результаты локальных проверок

- Playwright: итоговый прогон всей матрицы — **32/32** (Chromium, WebKit, Firefox и Android landscape), 23 адреса на 320/390/768 px, настройки и навигация.
- Vitest: 200 тестов / 20 файлов, включая шесть новых проверок настроек и haptic bridge.
- Полный `test:regression` прошёл: 39 Node-тестов и SQL-сценарии схемы/RLS, авторизации, уроков, контента, геймификации, социальных функций, платежей и администрирования.
- TypeScript, ESLint, Prettier и проверка diff прошли.
- Production Next.js build, Cloudflare Vite build и dry-run прошли. Секреты production в локальную среду не копировались; dry-run не проверяет их наличие в живом Worker.
- Локальный Cloudflare runtime: восемь браузерных сценариев настроек, навигации и всех экранов прошли без настоящих серверных секретов. Это проверяет интерфейс и состояния отсутствия авторизации, не личную запись в production Supabase.

Для Linux WebKit недостающие системные библиотеки установлены в пользовательский кэш. Браузер действительно запущен и выполнил тесты. Проверка системного ldconfig пропущена только в этом окружении после проверки запуска: она не видит пользовательские библиотеки; проверки приложения, TLS и авторизации не отключались. В обычном окружении использовать штатный `playwright install --with-deps`.

В обходе экранов каждый адрес открывается в отдельной вкладке одного браузерного контекста. Это проверяет прямой вход и не заменяет живой документ во время автоматической предзагрузки Next.js: в таком искусственном сценарии WebKit сообщал отменённый prefetch как ошибку access control. Ошибки каждого экрана и отсутствие переполнения проверяются до закрытия вкладки; ошибки не фильтруются. Клиентская навигация проверяется отдельным сценарием. Время обхода 23 экранов — до 90 секунд.
