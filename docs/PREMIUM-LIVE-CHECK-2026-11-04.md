# Проверка покупки Premium в Telegram Web

4 ноября 2026 года. Проверен бот Voklumi и открытое из него production Mini App в авторизованном Telegram Web пользователя. Платежи не включались, условия покупки не принимались, Stars не списывались.

## Подтверждённый результат

Покупка сейчас заблокирована. На странице Premium написано «Покупки пока выключены. Цена и условия будут доступны после проверки владельцем». Кнопка «Открыть оплату Telegram Stars» неактивна. Повторная проверка статуса не меняет это состояние.

Запрос production `/api/premium/invoice` с пустым JSON вернул HTTP 503 и «Платежи выключены. Владелец ещё не подтвердил запуск». Это подтверждает серверный запрет независимо от неактивной кнопки. В таблице star_orders на момент проверки 0 счетов и 0 оплаченных заказов. Проверка не дошла до Telegram invoice или pre-checkout; реальная выдача Premium после оплаты не подтверждена.

Локальная `cloudflare.config.ts` явно задаёт `TELEGRAM_STARS_PAYMENTS_ENABLED=false` и `TELEGRAM_STARS_OWNER_REVIEWED=false`. Для разрешения покупок `billingConfiguration` также требует реальную цену в Stars, HTTPS-страницы условий и поддержки, bot token и webhook secret. Включение флагов без остальных настроек не разрешит покупки. Значения production-секретов не извлекались.

## Дополнительный сбой входа

Mini App показывает «Telegram · вход не выполнен» и «Free · войди для проверки», хотя оно открыто из действующего аккаунта Telegram. Серверная проверка без чтения токенов подтвердила создание свежей сессии этого аккаунта при запуске приложения. Значит, отсутствие подписки на экране нельзя считать надёжной проверкой реального статуса пользователя: вход в приложение не завершён.

Вероятная причина — сессионная cookie: `src/lib/auth/session.ts` использует `SameSite=Lax`, а приложение встроено в iframe на другом сайте (`web.telegram.org` → `workers.dev`). Согласно [MDN](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie#samesitesamesite-value), Lax не включает cross-site iframe/fetch-запросы. Сочетание наблюдений согласуется с блокировкой cookie. Точный browser-level отказ Set-Cookie/Cookie в этой проверке не захватывался, поэтому это диагностическая гипотеза с подтверждённой несовместимостью текущей настройки для cross-site embedding, а не завершённое исправление.

Нужно проверить вариант cookie `HttpOnly; Secure; SameSite=None` для production и, при необходимости, поддержку partitioned cookies/ограничений сторонних cookie в целевых браузерах. Проверки Origin для изменений данных должны сохраняться. Требуются отдельные тесты cross-site iframe, обычного мобильного Telegram, выхода и отклонения чужого Origin. Настройки безопасности браузера пользователя не отключались.

## Что прошло отдельно

Повторно выполнены 4 Node-теста платежей и SQL-сценарий `scripts/test-payments.mjs`: выключенный checkout, подтверждение оплаты только серверным событием, проверка плательщика/суммы/валюты, срок и повтор invoice, повторные уведомления без двойной подписки, возвраты, поздние списания и закрытие Premium-доступа. Всё прошло на изолированной тестовой БД. Это не замена реальной операции Telegram Stars.

## Что требуется для завершения реальной проверки

1. Исправить и опубликовать вход в Telegram Web; подтвердить собственный аккаунт на странице Premium.
2. Подготовить и проверить цену, условия, канал поддержки и webhook. Текущая конфигурация публикации принудительно выключает продажи; её нужно менять осознанно при запуске.
3. Открыть настоящий счёт. Принятие условий покупки и окончательную оплату выполняет пользователь.
4. Проверить подписку в БД и интерфейсе после события successful_payment, обновление страницы и отказ в повторной выдаче доступа по тому же событию.

Снимок неактивной оплаты сохранён локально: `E:/SaaS/test-results/premium-live/premium-disabled.png`. Токены Telegram, сессий и приватные сообщения в отчёт не включены.
