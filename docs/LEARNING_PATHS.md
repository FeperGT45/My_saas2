# Этап B: персональные учебные маршруты

Работает поверх этапа A и прежнего движка уроков. Экран `/learning-plan`, API `/api/learning-plan`, независимый модуль `src/lib/learning/recommend.ts`. Из главной, профиля, настроек и старой карты есть переход к плану. Кнопка «Начать обучение» после placement открывает персональный план. Карта и статистика целиком не перерабатываются: это этап F. Новые типы заданий, библиотека и интервальное повторение остаются этапами C, D и E.

## Правила rules-v1

- Основа — последняя оценка английского из `user_language_levels`, либо выбранный пользователем уровень маршрута из этапа A. Пока старт не выбран, показывается переход к placement, без придуманного A1.
- Цели: общий английский, общение, игры, путешествия, учёба. Цель и выбранный курс сохраняются в `learning_paths`. Курс можно сменить в любой момент; предпочтение не закрывает остальные курсы.
- Берутся последние 30 завершённых попыток, из них только последняя попытка каждого урока. Повторное прохождение одного урока не считается несколькими разными освоенными темами.
- Если среди последних пяти разных уроков опорного уровня минимум три имеют результат от 80%, и ни один не ниже 60%, целевая сложность повышается на одну ступень. Две неудачи ниже 60% среди последних трёх таких уроков рекомендуют одну ступень проще. Границы A1–C2. Это сложность учебных рекомендаций, а не новая оценка CEFR.
- Навыки группируются по существующим типам заданий: grammar/gap/sentence → грамматика, single_choice/matching → словарь, listening → задания с аудио. Это приближённые группы, не лингвистическая разметка каждого вопроса. Аудиозадания могли проходиться с текстовым fallback: статистика не доказывает навык аудирования. После этапа C классификатор также учитывает reading/dialogue/response, новые грамматические и аудиоформаты; смешанный unit_test не выдаётся за один навык. Подробности — в EXERCISES.md.
- Для вывода о слабом навыке нужны минимум три ответа, доля верных менее 60%. Достаточные свежие данные уроков заменяют старое placement-свидетельство. Иначе используется только **последний** placement; история предыдущих тестов не смешивается.
- В начало ставится максимум два урока для закрепления: последняя оценка ниже 80%, минимум две ошибки в последней попытке и совпадение со слабым навыком. При успешном повторении рекомендация исчезает. Дополнительная практика использует реальные упражнения прежнего урока, без нового генератора заданий.
- Потом подбираются новые/неосвоенные уроки: сначала близость к целевой сложности, затем цель и слабые навыки, затем стабильный порядок курса. Автоподбор не перескакивает выше опорного уровня более чем на одну ступень. Явный ручной выбор курса позволяет учиться на другом уровне.
- План содержит до 12 шагов. Следующий шаг курса зависит от всех предыдущих опубликованных уроков этого курса с результатом от 60%. Будущие шаги показываются заранее с пояснением. Доступ к самому движку уроков не получает новых постоянных блокировок.
- Урок с лучшим результатом от 60% не навязывается как новый. Полностью освоенные темы не отправляются в бесконечный цикл: при отсутствии следующих шагов есть добровольные ссылки повторения, смена курса и честное пустое состояние.
- При нехватке материалов целевого уровня доступны близкие подходящие материалы. Новые уроки этапа D не выдаются за созданные. Если выбранный курс снят с публикации или недоступен по подписке, временно используется автоматический подбор. Права Premium по-прежнему определяет `can_access_lesson`.

## Данные и безопасность

Миграция `personal_learning_paths` добавляет `learning_paths` (одна английская программа на пользователя), `learning_path_lessons` и `courses.learning_goals`. Новые дубли `exercise_attempts` и `user_skill_levels` не создаются: используются существующие `exercise_submissions`, `lesson_attempt_items`, `lesson_attempts` и `user_skill_assessments`. Последовательность курса берётся из позиций разделов/уроков. Уроки без доступных упражнений, неопубликованные и недоступные материалы не рекомендуются.

Новые таблицы закрыты RLS и отсутствием клиентских привилегий. Четыре RPC доступны только service role. Это соответствует существующей архитектуре: пользователь определяется сервером по непрозрачной HttpOnly Telegram-сессии, а не клиентскому UUID или `auth.uid()` фиктивной локальной сессии. У SECURITY DEFINER фиксированный пустой search_path, EXECUTE отозван у PUBLIC/anon/authenticated. API не принимает пользователя, оценки, XP, список шагов или ответы. Все тела проходят строгую валидацию и ограничение размера; изменяющие запросы проверяют Origin. Ответы API имеют `Cache-Control: no-store`.

Сервер читает минимальный контекст без ключей ответов, строит план чистой функцией, затем атомарно сохраняет его. Запись берёт тот же user-lock, что движок уроков. Хеш контекста обнаруживает изменение прогресса/предпочтений между чтением и сохранением; сервер перечитывает данные максимум один раз. Сохранение проверяет доступность всех шагов, отсутствие дублей и порядок предпосылок. Одинаковые входы/план не создают новых записей. Старый план при ошибке валидации остаётся целиком благодаря транзакции.

`GET /api/learning-plan` вычисляет актуальный план без записи. `POST {action:"refresh"}` сохраняет его при открытии экрана; после каждого урока следующее открытие учитывает новые результаты. `POST {action:"preferences",goal,courseId}` сохраняет выбор и перестраивает план. Placement после завершения/выбора A1 также пытается сохранить план; если база временно недоступна, placement не откатывается, экран плана безопасно повторяет генерацию.

Обновление маршрута не пишет XP, валюту, результаты placement, ответы или `user_progress`. Прежняя транзакционная защита наград сохраняется. Для ограничения стоимости на бесплатном Cloudflare нет AI, cron, фоновых очередей или внешних рекомендательных сервисов; на открытие — чтение контекста и идемпотентное сохранение. Текущий каталог небольшой; перед расширением далеко за 300 уроков следует повторить EXPLAIN и нагрузочные проверки.

## Настройка и проверки

Новых переменных окружения и секретов нет. Применить миграцию `personal_learning_paths` после миграций этапа A. `npm run learning:check` проверяет две таблицы, RLS и RPC-права; `npm run build:production` теперь включает эту проверку перед Worker-сборкой.

Команды: `npm run test:learning`, `npm run test:unit`, `npm run test:regression`, `npm run lint`, `npm run typecheck`, `npm run format:check`, `npm run build`, `npm run test:ui`; затем `npm run build:cloudflare`, `npm run check:cloudflare`, `npm run test:cloudflare` на поддерживаемом Node.js.

Vitest проверяет чистые правила, выбор уровня/цели, ограничения повышения, слабые навыки, предпосылки, fallback, повторное тестирование, сохранность прогресса/XP, транзакции и права PostgreSQL через PGlite. Playwright проверяет реальный Next API с HttpOnly-сессиями и изолированным HTTPS PostgREST/PGlite, автоматическое создание после A1, выбор курса/цели, reload, ошибки/повтор, чужие аккаунты, мобильную ширину и axe. Отдельный SQL-backed транспорт проверяет тот же клиент на Worker. Это не заменяет физическую проверку Telegram на телефоне и внешнюю методическую калибровку.
