# Интерактивные истории Voklumi

## Результат

Раздел `/stories`, ссылки с карты уроков и профиля. Каталог и движок не зависят от названий или числа историй. Все сюжеты написаны для проекта; готовые произведения и внешние AI/платные API не использованы. Озвучки нет.

95 узлов, 110 переходов, 15 концовок и 10 учебных заданий. Уровни — редакционные ориентиры сложности текста, не сертификация CEFR. В каждом узле есть словарная подсказка; грамматические пояснения доступны в заданиях и ключевых сценах. Ошибки получают объяснение и ведут к альтернативным сценам. Последнее задание меняет набор доступных развязок.

## Движок и сохранение

`interactive_stories` хранит метаданные и JSON-граф. `story_attempts` — текущий узел, выбранные переходы, версии, счётчики заданий и состояние попытки. `story_choice_events` — закрытый журнал идемпотентности. `story_endings` — личная коллекция полученных концовок и памятных значков.

Сервер возвращает только текущую сцену, допустимые реплики и уже прочитанный диалог. Полный граф, следующие узлы и поля правильных ответов клиенту не передаются. Ссылку с `?attempt=…` можно открыть позже; состояние загружается из Supabase. Каждый выбор фиксируется одной транзакцией вместе с результатом задания и новой концовкой. Смена сцены не требует отдельного сохранения пользователем.

Запросы имеют UUID; повтор после потери ответа не проходит второй узел и не дублирует награду. Версия попытки блокирует устаревшие ответы и гонки вкладок. Сервер разрешает только переходы из текущего узла. Новый старт архивирует активную попытку этой истории как `abandoned`, сохраняя путь; завершённые попытки остаются. Одна активная попытка истории на пользователя обеспечивается уникальным индексом и блокировкой операций пользователя.

Награда — именованный коллекционный значок за каждую впервые полученную концовку. Повторное прохождение той же концовки её не дублирует. Уникальность действует между редакциями сюжета по `(user_id, story_slug, ending_id)`. Значки видны в «Мои концовки»; общий XP, монеты и награды обычных уроков не меняются.

## Premium и безопасность

Одна опубликованная A1-история доступна Free. Полный каталог использует центральное серверное право `extra_exercises`. Каталог показывает метаданные закрытых историй и ссылку на Premium. Сервер проверяет право при старте, каждом выборе и загрузке текста. Окончание подписки закрывает текст платной истории, сохраняя место, результаты и значки; повторная активация позволяет продолжить ту же попытку. История полученных концовок доступна и после окончания Premium.

`/api/stories` использует существующую проверенную Telegram-сессию. `user_id` и Premium-флаги из клиента не принимаются. Изменения требуют JSON и того же origin; размер тела ограничен 4 KiB. UUID, поля команд и параметры чтения проверяются строго. Нет маршрута самостоятельного начисления наград или редактирования графа.

RLS включён на всех четырёх таблицах. Клиент может читать только метаданные опубликованных историй и собственные попытки/концовки. На `document` нет клиентского SELECT; прямые изменения закрыты. Журнал выборов закрыт для клиентских ролей. RPC имеют фиксированный `search_path`, работают как invoker и доступны только service_role. Служебный ключ остаётся на сервере. Индексы покрывают владельца, активную попытку, версии историй и внешние ключи.

Политики соответствуют разделению grants и RLS из [документации Supabase](https://supabase.com/docs/guides/database/postgres/row-level-security). После применения новых WARN безопасности нет. Дополнительная [INFO «RLS без политик»](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy) относится к закрытому `story_choice_events`: клиентских grants намеренно нет. Прежние предупреждения [anon helper](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable), [authenticated helper](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable) и [защиты паролей](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection) не изменились.

## Добавление историй

1. Добавить объект `StorySource` в `content/stories/originals.ts`. Схема описана в `src/lib/stories/types.ts`: уникальный slug, revision, уровень, описания, стартовый узел и граф.
2. У каждой сцены — английский текст, персонаж, подсказки, реплики с ID и целевыми узлами. Задание содержит вопрос, объяснение и варианты с серверными признаками `correct`; концовка — название и значок без исходящих переходов.
3. Выполнить `npm run stories:content`, затем `npm run stories:seed`. Проверяются достижимость всех узлов, отсутствие циклов/тупиков, уникальность реплик, валидность целей и заданий. Допустимы 15–80 узлов, до четырёх вариантов, минимум две концовки, два задания и три развилки; документ до 200 KiB.
4. Применить миграции и сгенерированный `supabase/stories-seed.sql` или выполнить `npm run stories:import` с серверными переменными окружения. Импорт проверяет совпадение сохранённого содержимого. Начальная конфигурация Supabase также включает seed историй.
5. Граф опубликованной редакции неизменяем. Для изменения сюжета создать новую revision и в одной редакционной транзакции снять `published` со старой и опубликовать новую. Старые попытки продолжают читать свою редакцию. Стабильные ID концовок сохраняют ранее выданные значки. Удалять старые редакции с прогрессом нельзя.

React-компоненты менять не требуется. Каталог выдаёт до 100 опубликованных историй; длинная история разбивается на отдельные публикации по техническим пределам. `stories:check` проверяет готовность схемы и каталога перед production-сборкой, при ошибке выпуск блокируется.

## Применение и проверки

Миграция `20261104120225_interactive_stories.sql` и пять историй применены в Supabase `wpctwlgfnkekgulgkxad`. Проверено `stories-v1`, `ready: true`, пять опубликованных историй по 19 узлов и три концовки. Проверочных пользовательских попыток и наград в рабочей базе не создавалось. Новый интерфейс не опубликован в Cloudflare.

`tests/unit/stories.test.ts` проходит все 110 переходов через SQL-движок, проверяет три концовки каждого сюжета, эталон содержимого, недопустимые графы/команды, неизменяемость редакций, идемпотентность, устаревшие ответы, перепрохождение, Free/Premium, окончание/возобновление подписки, глобальное выключение права и RLS/привилегии.

Прошли 164 unit-теста в 14 файлах и 13 проверок production preflight, ESLint и Prettier. Сборки Next.js (включая TypeScript) и Cloudflare/Vite завершились успешно. Прежние предупреждения Vinext о sourcemap и оптимизации импортов lucide не препятствуют сборке.

Два браузерных сценария Next.js прошли: настоящий API с изолированной PostgreSQL и сессиями проверяет каталог, обе разновидности развилок, переводы, потерю ответа и безопасный повтор, перезагрузку, награду, перепрохождение, окончание/возобновление Premium и чужие ID; отдельный сценарий проверяет входной экран и запрет анонимных запросов. На ширине 320 px нет горизонтального переполнения; автоматический аудит WCAG 2 A/AA каталога и концовки не нашёл нарушений. Скриншоты: `artifacts/interactive-stories/catalog.png` и `artifacts/interactive-stories/ending.png`.

На локальном Cloudflare Worker также прошёл сценарий входного экрана и запрета анонимных запросов. Preview работает без рабочих секретов: полный авторизованный сценарий Worker не запускался. Авторизованные операции проверены через настоящий Next API и изолированную БД. При отсутствии APP_URL preview отклоняет POST по origin ещё до проверки сессии; настроенный тестовый сервер отдельно подтверждает 401 без сессии и 403 для чужого origin. Рабочий интерфейс Cloudflare не обновлялся.
