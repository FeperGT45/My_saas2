# Premium и Telegram Stars

Подготовленный режим Voklumi: разовая покупка доступа Premium на **30 × 24 часа**, без автопродления. После окончания срока остаются Free, XP, рейтинг и сохранённый прогресс. Текущий этап не включает реальные платежи, не меняет удалённую базу и не назначает цену.

## Официальные требования

Документация проверена 2 ноября 2026 года:

- [Оплата цифровых товаров через Stars](https://core.telegram.org/bots/payments-stars): внутри Telegram используется валюта `XTR`, без внешних платёжных провайдеров. Пользователю нужны условия покупки и доступная поддержка `/paysupport`; спорные покупки и возвраты обрабатывает владелец.
- [createInvoiceLink](https://core.telegram.org/bots/api#createinvoicelink): для Stars пустой `provider_token`, ровно один элемент `prices`. Наш SKU не передаёт `subscription_period`.
- [answerPreCheckoutQuery](https://core.telegram.org/bots/api#answerprecheckoutquery): Telegram должен получить ответ за 10 секунд. Наши бюджеты — 2,5 секунды на проверку БД и 2,5 секунды на ответ Bot API; задержка доставки и холодного старта также должна быть проверена владельцем.
- [SuccessfulPayment](https://core.telegram.org/bots/api#successfulpayment): доступ выдаётся после `successful_payment`; `telegram_payment_charge_id` сохраняется для идемпотентности и возврата.
- [refundStarPayment](https://core.telegram.org/bots/api#refundstarpayment) и [RefundedPayment](https://core.telegram.org/bots/api#refundedpayment): полный возврат конкретного платежа и подтверждение возврата. Частичный возврат в реализации не предусмотрен.
- [editUserStarSubscription](https://core.telegram.org/bots/api#edituserstarsubscription) относится к автопродлеваемым подпискам. Такой SKU здесь не создаётся, поэтому запрос отмены продления не отправляется. «Завершение подписки» для нашего тарифа означает истечение оплаченного срока.

## Данные и доступ

Миграция `supabase/migrations/202611020009_stars.sql` добавляет закрытые `star_orders`, `star_events`, связь оплаченного периода с заказом, уровни курсов и отметку дополнительных упражнений. У клиентских ролей нет доступа к журналам платежей и исполняемым RPC начисления. Существующая таблица `subscriptions` сохраняется; старые записи без подтверждённого Stars-заказа сами по себе Premium не открывают.

`create_star_order` привязывает заказ к пользователю из проверенной серверной сессии и его сохранённому Telegram ID. Цена берётся из серверного окружения, не из запроса браузера. Один пользователь имеет не больше одного открытого заказа. Повторный request ID и параллельные открытия возвращают существующий заказ. Срок проверки счёта — 30 минут; повтор одного pre-checkout query разрешён, другой query для уже зарезервированного счёта отклоняется. После отмены/истечения счёта может потребоваться открыть новый после его TTL.

Webhook сначала проверяет `X-Telegram-Bot-Api-Secret-Token` сравнением за постоянное время. Затем сверяет покупателя, payload, валюту, сумму и charge ID с заказом. Pre-checkout только резервирует заказ, без прав доступа. `apply_star_event` одной SQL-транзакцией блокирует пользователя и заказ, записывает событие, создаёт период доступа. Дубликат не продлевает срок. Разные подтверждённые платежи, пришедшие поздно, сохраняют отдельные последовательные 30-дневные периоды. Возврат одного платежа не отнимает другой оплаченный период и не оставляет бесплатного промежутка из возвращённого заказа.

Подтверждённый возврат отзывает соответствующий период. Возврат раньше сообщения об успешной оплате создаёт запись, которая блокирует последующее восстановление этого платежа. Состояние `refund_pending` сохраняет права до фактического подтверждения возврата. Отключение новых покупок не блокирует обработку старых квитанций и возвратов.

Права проверяются при старте, получении состояния и ответе в уроке. Политики RLS ограничивают чтение закрытых уроков и дополнительных заданий. Окончание Premium во время такого задания останавливает попытку; сохранённые результаты не удаляются. Можно начать доступный Free-урок заново. Правильные ответы по-прежнему не уходят клиенту до проверки.

## API и интерфейс

- `GET /api/premium` — собственный статус, дата окончания, флаг доступности покупки, цена и ссылки на условия/поддержку.
- `POST /api/premium/invoice` — только `{ requestId: UUID, acceptTerms: true }`, Telegram-сессия и проверка Origin. Произвольная сумма или user ID отклоняются.
- `GET /api/premium/features` — только Premium: точность ответов, завершённые попытки и до пяти уроков на повторение. Интервал от последней завершённой попытки: 1 день при лучшем результате ниже 60%, 3 дня ниже 90%, иначе 7 дней. Это прозрачное правило, не AI-рекомендации.
- `/premium` — мобильный экран Free/Premium, состояние загрузки/ошибки, подтверждение условий, Telegram invoice SDK и ручное обновление статуса. Результат закрытия invoice-окна не выдаёт доступ.

Сейчас весь существующий контент остаётся Free. После импорта каталога файл `supabase/premium-policy.sql` может отдельно сделать Gaming English и Internet English платными, оставив первые два урока каждого бесплатными; Basic English сохраняется Free. Автоматически этот файл не выполняется. Дополнительные упражнения поддерживаются через `exercises.premium_only`, но готовый отдельный платный набор в этом этапе не публикуется. Интерфейс указывает их доступность при наличии материалов.

## Конфигурация перед ручной проверкой

Задайте значения через Environment variables/Secrets в окружении Codex Cloud и отдельно в production-хостинге. Не отправляйте секреты в переписку, не добавляйте их в Git или публичные переменные.

| Переменная                              | Назначение                                                                  |
| --------------------------------------- | --------------------------------------------------------------------------- |
| `TELEGRAM_STARS_PAYMENTS_ENABLED=false` | Переключатель новых оплат; оставить выключенным до ручной проверки          |
| `TELEGRAM_STARS_OWNER_REVIEWED=false`   | Отдельная отметка проверки владельцем                                       |
| `TELEGRAM_STARS_PREMIUM_PRICE`          | Утверждённая целая цена в Stars, без значения по умолчанию                  |
| `PREMIUM_TERMS_URL`                     | Публичная HTTPS-страница условий, сроков доступа, возвратов                 |
| `PAYMENT_SUPPORT_URL`                   | Рабочий HTTPS-адрес поддержки покупок                                       |
| `TELEGRAM_BOT_TOKEN`                    | Серверный Secret бота; для тестового окружения отдельная конфигурация       |
| `TELEGRAM_WEBHOOK_SECRET`               | Независимый серверный Secret длиной от 32 символов                          |
| `APP_URL`                               | Публичный HTTPS origin размещённой Mini App                                 |
| `NEXT_PUBLIC_SUPABASE_URL`              | URL выбранного Supabase проекта                                             |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`  | Публичный ключ этого проекта                                                |
| `SUPABASE_SECRET_KEY`                   | Серверный Secret Supabase; альтернативно legacy `SUPABASE_SERVICE_ROLE_KEY` |
| `TELEGRAM_STARS_REFUNDS_ENABLED=false`  | Отдельный операторский переключатель возвратов                              |
| `STARS_REFUND_ORDER_ID`                 | Внутренний UUID возвращаемого заказа, только окружение оператора            |

Диапазон 1–10000 Stars — ограничение цены этого приложения, не утверждение об общем лимите разовых счетов Bot API. Платежи не включаются при неполной конфигурации. `ENABLE_LOCAL_AUTH` не выдаёт Premium и не допускается к платёжным API.

## Проверка владельцем до запуска

1. Подготовить backup и отдельный staging-проект. Применить все текущие миграции по порядку (Stars: 009, админ-панель: 010) и выполнить `npm run db:check`. Последняя ранее проверенная удалённая схема — **008 / 19 таблиц**; текущий код после добавления админ-панели ожидает **010 / 22 таблицы**. 009/010 удалённо не применялись; настройка панели описана в [ADMIN.md](ADMIN.md).
2. Утвердить цену, состав платных материалов, опубликованные условия и рабочую поддержку. Проверить `/terms`, `/paysupport`, согласие пользователя и действия при спорной покупке.
3. Разместить Mini App на HTTPS, настроить BotFather и webhook с секретом; `npm run telegram:setup` регистрирует команды и `allowed_updates: message, pre_checkout_query`. Скрипт вызывает реальный Bot API и не запускался в этом этапе.
4. Выполнить локальные тесты. Для интеграционного платежа следовать разделу тестирования официальной документации Stars и использовать изолированное тестовое окружение Telegram с отдельными настройками. Код Bot API по умолчанию использует production endpoint; автоматического переключателя в тестовый endpoint здесь нет. Не включать production-флаги ради теста и не считать локальные fixtures реальным платежом.
5. Проверить в реальном мобильном Telegram доставку webhook, задержку pre-checkout, отмену окна, подтверждение, повтор уведомления, потерю соединения после списания, возврат, срок доступа и восстановление после перезапуска. Только после этой проверки владелец отдельно выставляет оба разрешающих флага и запускает реальные оплаты.

## Возврат и сверка

После рассмотрения обращения владелец выбирает внутренний order UUID. При настроенных секретах, `TELEGRAM_STARS_OWNER_REVIEWED=true`, `TELEGRAM_STARS_REFUNDS_ENABLED=true` и `STARS_REFUND_ORDER_ID` команда:

```bash
npm run stars:refund -- --confirm-owner-refund
```

вызывает реальный `refundStarPayment`. Это операторская команда; публичного маршрута возврата с произвольными Telegram ID/charge ID нет. Уже записанный возврат не вызывает API повторно. До подтверждения API сохраняется `refund_pending`. После успешного API и сбоя записи БД нужно сверить платёж перед повторным вызовом: подтверждение через webhook может завершить запись. Команда не печатает токены и реквизиты платежа.

Неизвестный заказ, несовпадение реквизитов или ошибка записи дают webhook ответ 503 для повторной доставки, без выдачи прав. Настройте мониторинг таких ответов и ручную сверку с Telegram; для поиска операций существует официальный [getStarTransactions](https://core.telegram.org/bots/api#getstartransactions). Автоматический импорт этой истории и панель обработки споров в текущий этап не входят. Сетевой timeout возврата не доказывает, что возврат не был выполнен: сначала сверяйте статус, затем повторяйте.

## Что проверяется локально

`npm run test:payments` проверяет конфигурацию, XTR-счёт, разницу pre-checkout/receipt, точные реквизиты, запрет клиентского изменения оплаты, SQL-транзакции и идемпотентность, разные поздние платежи, возврат и порядок уведомлений, истечение срока, RLS, Free-превью, платные задания и статистику. Используется настоящая PostgreSQL-семантика PGlite с миграциями и тестовыми данными, без списания Stars.

`npm run test:ui` проверяет мобильный экран на 320px, отключённую покупку, реальные SQL-статусы active/expired/refunded через тестовую подмену транспорта и закрытый анонимный API. Полный платёжный цикл в Telegram, нагрузка нескольких PostgreSQL-соединений и удалённая миграция 009 здесь не проверялись.
