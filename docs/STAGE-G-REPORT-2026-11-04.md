# Voklumi: комплексная проверка, этап G

Проверка 3–4 ноября 2026 года. Исходная версия приложения: `0260814`. Изменения этапа G не опубликованы в GitHub/Cloudflare. Production Supabase проверялся только на чтение; тестовые пользователи, ответы и оплаты в него не добавлялись.

## Исправления

1. HTTPS-окружение сквозных тестов зависело от системного OpenSSL и не запускалось на этом Windows-компьютере. Сертификат теперь генерируется библиотекой `selfsigned` 5.5.0 с SHA-256 в памяти. Временный доверенный сертификат передаётся только дочернему тестовому серверу. Проверка TLS не отключается; приложение не получило обходов авторизации.
2. Подготовка production-сборки запускала `npm` как Unix-программу. В окружении npm теперь используется его фактический JavaScript-файл через текущий Node.js. Проверены успешная последовательность и остановка при ошибках.
3. Проверки подготовки релиза использовали неподдерживаемый Windows-путь для `--import`, Unix-разделитель PATH и сравнение SQL с зависимостью от CRLF. Исправлены переносимость и сравнение окончаний строк.
4. Браузерные проверки обновлены для живого каталога и названия «Уровень опыта». Страница повторения добавлена в обход экранов и аудит доступности. Проверка отказа анонимным запросам и поддельным ролям расширена на новые личные API.
5. Добавлен сквозной тест `/api/review` и `/api/overview` на настоящем production-сервере Next.js с изолированным PostgreSQL PGlite и HTTPS-транспортом. Он проверяет потерю ответа сети после сохранения, повтор с тем же идентификатором, одну запись события, сохранение после перезагрузки, обновление статистики, неизменность XP, отказ чужому пользователю, поддельному userId и чужому Origin.
6. Артефакты Cloudflare-тестов вынесены в отдельную папку, чтобы независимые запуски не удаляли трассировки друг друга.

Тесты определения уровня проверяют начальный A1, повышение/понижение сложности, отсутствие повторных вопросов, 12–20 вопросов, возобновление, лимит попыток, неопределённость результата и сохранение прежнего прогресса. Worker собирается с предупреждениями vinext о sourcemap, оптимизации импортов и статической классификации маршрутов. Ошибок сборки нет; эти предупреждения не считаются доказательством отказа маршрутов. TypeScript следует запускать через `npm run typecheck`: он сначала генерирует типы Next.js, которые может перезаписать vinext. На этой машине проверки запускались с ограничением памяти и последовательно после обнаруженного исчерпания памяти при одновременных тяжёлых процессах.

Упражнения проверяются на сервере с положительными/отрицательными ответами, нормализацией и снимками содержимого попытки. Проверены повторная отправка, потеря ответа, порядок заданий и однократные награды. SRS проверен на интервалы, ошибки, версии карточек, повтор запросов и изоляцию пользователей.

Мобильные экраны проверены при ширине 320, 390 и 768 px, увеличении текста, отключённой анимации и навигации с клавиатуры. Автоматический axe-аудит использует WCAG 2 A/AA и WCAG 2.1 AA; это не замена ручной проверки доступности. Синтез речи проверен с текстовым запасным вариантом.

## Supabase и безопасность

- Core, placement, learning и curriculum readiness: `true`. Применены миграции SRS и статистики.
- 92 урока всего: 90 полноценных и 2 вводных; 727 упражнений и 120 вопросов определения уровня. Пакет `english-path-core` revision 2: 60 уроков/480 упражнений. Локальные валидаторы библиотеки, основного контента и банка вопросов прошли без импорта в production.
- Обычных таблиц public без RLS: 0. Прямое чтение/запись карточек клиентскими ролями закрыты. Новые RPC определения уровня, маршрутов, повторения и статистики недоступны `anon` и `authenticated`; пользователь определяется серверной сессией.
- Аудит Supabase сообщает 17 закрытых серверных таблиц с RLS без политик. Это соответствует отказу клиентам и доступу через сервер, а не требованию открыть таблицы.
- `current_user_has_premium()` имеет SECURITY DEFINER и доступна клиентским ролям. Проверено тело: только `has_premium(auth.uid())`, без произвольного пользовательского ID; функция нужна существующим RLS-политикам. Произвольный доступ к подпискам не подтверждён. [Описание замечания](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable).
- Защита от утёкших паролей выключена. Пользовательский вход приложения выполняется через Telegram; перед включением паролей настройку нужно пересмотреть. [Настройка Supabase Auth](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).
- Performance Advisor: 4 внешних ключа без покрывающих индексов в placement answers, language levels, skill assessments и XP events. Это рекомендация при росте данных; производственная схема в рамках проверки не менялась. [Пояснение](https://supabase.com/docs/guides/database/database-linter?lint=0001_unindexed_foreign_keys). Неиспользуемые индексы автоматически не удалялись.
- Выборка журналов за последние 24 часа не нашла записей с `error_severity` ERROR/FATAL. Это ограниченная проверка поля журнала, а не гарантия отсутствия любых ошибок.
- `npm audit --omit=dev`: известных уязвимостей нет. Полный audit: 16 предупреждений moderate из цепочки инструментов ESLint, корневая причина — `minimatch` <11.0.1. [Advisory GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249). Принудительная замена major-версии старых зависимостей не выполнялась: требуется совместимое обновление цепочки ESLint. Production-зависимости эту находку не содержат.
- Поиск характерных приватных ключей и токенов среди 286 отслеживаемых файлов нашёл только намеренную тестовую строку `sb_secret_CREDENTIAL_DO_NOT_LOG`. Это ограниченный поиск шаблонов, а не полный анализ всей истории Git.

## Развёрнутая версия и ограничения

Проверены read-only HTTP-запросы к `https://voklumi.voklumi67.workers.dev`: health/library — 200, placement/learning-plan без сессии — 401. В библиотеке не обнаружены поля answer_key, token_hash или service_role. `/api/overview` возвращает 404: опубликованный Worker отстаёт от локальных этапов E/F. Работоспособность старого сайта не доказывает публикацию новых возможностей.

Локальные сквозные тесты используют изолированную БД и настоящие обработчики Next.js. Часть сценариев при выборе Cloudflare-конфигурации также поднимает этот отдельный Next.js-сервер; остальные проверяют Worker с подменённым транспортом API и реальными SQL-результатами. Локальный Worker запущен без production-секретов. Это не проверка настоящего Telegram-входа или живой авторизованной записи Worker → production Supabase.

Не проверялись: Telegram на физическом телефоне, реальная доставка webhook, покупка/возврат Stars, нагрузка и одновременная работа множества пользователей. Платежи остаются выключенными. Полная `build:production` с настоящим Telegram getMe и production-секретами локально не запускалась; логика её блокировок проверена отдельно.

Для выпуска: отправить проверенные коммиты в GitHub, дождаться сборки Worker и проверить настоящий вход, один урок, повторение и обновление профиля на телефоне. Секреты должны оставаться в настройках сборки/runtime Cloudflare. Текущие проверки перед публикацией охватывают core/placement/learning/exercises/curriculum; отдельной проверки готовности схем E/F в скрипте публикации пока нет, поэтому их миграции следует проверять перед выпуском.

Библиотека ещё не достигла цели 300 качественных уроков: остаются 210 полноценных уроков. Автотесты структуры и ответов не заменяют экспертную редактуру всего учебного содержания и калибровку CEFR.
