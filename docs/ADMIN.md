# Административная панель Voklumi

Панель доступна по `/admin` и ссылке «Администрирование» в профиле. Она работает с текущей Supabase-схемой и не использует демонстрационные списки пользователей или поддельные права. Название проекта остаётся Voklumi.

## Настройка доступа

1. Войти в приложение через Telegram, чтобы был создан проверенный сервером профиль.
2. В защищённом Supabase Dashboard найти внутренний UUID нужного профиля в `public.users`. Проверить принадлежность аккаунта владельцу; имя/username сами по себе не подтверждают личность.
3. В Codex Cloud → Settings → Environments → окружение репозитория задать **серверную закрытую конфигурацию** `ADMIN_USER_IDS`: внутренние UUID через запятую. В production задать её отдельно в настройках серверного хостинга. Не использовать префикс `NEXT_PUBLIC_`, клиентские роли или user metadata. Не присылать серверные ключи в переписку и не сохранять их в Git.
4. Перезапустить процесс после изменения конфигурации. Пустой список закрывает панель для всех; ошибка хотя бы в одном UUID также закрывает доступ. Поддерживается до 100 UUID без завершающей запятой.
5. Открыть `/admin` после Telegram-входа. Если страница была открыта до создания сессии, нажать «Обновить доступ».

Дополнительно нужны существующие серверные настройки Supabase и Telegram: `NEXT_PUBLIC_SUPABASE_URL`, публичный ключ, один из `SUPABASE_SECRET_KEY` / `SUPABASE_SERVICE_ROLE_KEY`, токен бота для проверки Telegram initData, корректный `APP_URL`. `APP_URL` используется для проверки Origin при сохранении. Секреты задаются средствами окружения, а не в браузерной форме.

Локальная демо-сессия не допускается в панель, даже если её идентификатор случайно попал в список. Администраторов нельзя назначить через форму, заголовок запроса или публичный API. Удаление UUID из конфигурации и перезапуск отзывают доступ при следующей серверной проверке.

## База данных

Миграция `202611020010_admin.sql` добавляет:

- `admin_version` у курсов, разделов, уроков и заданий; версия увеличивается при каждом изменении, включая внешние импорты;
- закрытый журнал `admin_audit_events`;
- серверные RPC `admin_read` и `admin_save_content`;
- readiness-проверку схемы **202611020010 / 22 таблицы**.

Миграция подготовлена и проверена локально; удалённо не применялась. В текущем окружении серверные секреты не настроены. Последнее подтверждённое удалённое состояние из предыдущего этапа — 008 / 19 таблиц. Перед размещением новой версии примените недостающие миграции **009, затем 010** по порядку к staging, проверьте и затем примените к нужному проекту с backup. Не запускайте reset существующей базы. Общая инструкция CLI/SQL Editor находится в README, раздел Supabase.

```bash
npm run test:admin
npm run test:db
npm run db:check
```

`db:check` требует настройки реального окружения. Локальные тесты используют PGlite и не подтверждают удалённое применение. Платёжные переключатели остаются выключенными; админ-панель их не включает.

## Возможности

- **Обзор:** число учеников и курсов, опубликованные уроки, активные ученики, начатые и завершённые попытки за 7 дней, средний результат. Процент завершения считается для попыток, начатых за последние 7 дней; число завершений учитывает время завершения. Активность означает учебные попытки, а не просмотр экранов или онлайн-присутствие.
- **Ученики:** поиск по имени, внутренний UUID, дата регистрации, XP, завершения и время последнего занятия. Сессионные токены, Telegram ID/username, реферальные коды и служебные секреты в списке не выдаются.
- **Контент:** курс → раздел → урок → задание. Можно создавать и редактировать названия, порядок, язык, уровень, XP, публикацию, Free/Premium-доступ и бесплатные превью. Перенос существующего раздела/урока/задания в другого родителя не допускается, чтобы не менять смысл сохранённой истории.
- **Задания:** удобные поля вместо JSON для всех шести форматов: варианты с выбором правильного, слова с порядком ответа, пропуск с допустимыми ответами, пары слов, грамматика, текст/язык аудирования. Правильные ответы доступны только авторизованному администратору.
- **Активность:** последние попытки с именем, уроком, состоянием, временем и результатом.
- **Подписки:** просмотр плана, срока, статуса и состояния связанного платежа. Истёкший срок отображается как истёкший даже при старом `active`. Charge ID и provider reference не возвращаются. Изменять подписку или выдавать неоплаченный Premium через панель нельзя.
- **Журнал:** кто, когда и какую сущность создал/изменил, UUID и новая версия. Полные ответы и персональные данные в журнал не копируются.

Списки ограничены 25 записями на страницу. Поиск доступен для курсов, учеников, активности и подписок. Формы показывают ошибки проверки, конфликты версии и недоступность базы без внутренних SQL-ошибок.

## Редактирование и публикация

Сначала создать курс-черновик, затем раздел, урок-черновик и задания. Урок можно публиковать после добавления хотя бы одного обычного задания; курс — после публикации хотя бы одного урока. Последнее обычное задание опубликованного урока нельзя сделать исключительно Premium. Для скрытия курса/урока снять «Опубликовано» и подтвердить сохранение. Физического удаления пользователей, истории, платежей и контента в панели нет.

Каждое сохранение требует отдельного подтверждения с названием объекта. Сервер также проверяет подтверждение, привязанное к типу и UUID. Это защита от случайного действия, а не замена авторизации. Публикация, скрытие и изменение доступа влияют на новые обращения; платные/скрытые задания повторно проверяются движком урока. Уже созданные попытки сохраняют свои снимки содержания и XP. Результаты и платежи не переписываются.

При конфликте версии изменения не применяются: обновить список, открыть свежую запись и повторить редактирование. При сетевой ошибке можно повторить тот же запрос: request UUID и отпечаток данных предотвращают второе действие и второй журнал. Если после ошибки изменить поля, форма создаёт новый request UUID. Изменение и журнал выполняются одной SQL-транзакцией; ошибка откатывает оба.

Панель управляет реальными таблицами контента; браузерный демонстрационный каталог приложения сохраняет существующую реализацию. Публикация записи в БД не добавляет её в статические демонстрационные карточки. Серверный движок уроков и RLS используют настройки БД.

## Граница безопасности

Страница проверяет серверную HttpOnly Telegram-сессию до выдачи интерфейса редактора. Каждый GET/POST `/api/admin` повторно проверяет эту сессию и серверный allowlist. Смена клиентского состояния не выдаёт прав. Редактор привязан к исходному аккаунту страницы, чтобы смена пользователя не показывала загруженные данные другому аккаунту.

POST требует тот же Origin, JSON и размер до 32 КБ. Разрешены только известные сущности и поля; проверяются UUID, длины строк, диапазоны чисел, варианты, порядок слов и соответствие правильных ответов. Публичные exercise payload не принимают поля с ответами. Сохранение существующей записи требует текущую версию. Значения в интерфейсе выводятся текстом, без произвольного HTML.

`anon` и `authenticated` не могут читать журнал, вызывать административные RPC или менять таблицы. Серверная service-role остаётся привилегированной: SQL RPC доверяют ей и переданному ею actor UUID. Сам список администраторов находится в серверной конфигурации, поэтому его проверяет Next.js перед RPC; обладатель service key уже имеет административный доступ к БД. Не выдавайте этот ключ клиенту или обычному пользователю.

## Проверки

- `npm run test:admin`: отказы анонимному, обычному, локальному и просроченному пользователю; поддельные роли/заголовки; пустая/сломанная конфигурация; Origin; строгая валидация всех типов; лимиты; скрытие ошибок; реальные SQL-права/RLS, CRUD, журнал, повторные запросы, конфликты версии, rollback, приватность и снимки попыток.
- `npm run test:ui`: дополнительно настоящий production Next.js с изолированным HTTPS PostgREST-адаптером к PGlite. Используются реальные серверные cookie-проверки и API, без тестового обхода в приложении. Проверены отказ ученику/истёкшей сессии, редактор на 320px, отмена/подтверждение действия, создание всей цепочки контента, чтение разделов и отзыв сессии.
- Общие lint, TypeScript, форматирование, сборка и регрессионные тесты уроков, контента, геймификации, платежей и социальных функций остаются доступны.

Удалённая Supabase, реальные production-сессии и Telegram WebView в этом этапе не проверялись. Нагрузочные гонки нескольких отдельных PostgreSQL-соединений не моделировались.
