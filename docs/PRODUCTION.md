# Текущее размещение Voklumi

Проверено 3 ноября 2026 года. Адрес: https://voklumi.voklumi67.workers.dev.

GitHub main подключён к Workers Builds. Production build: `npm run build:production`.
Deploy: `npm run deploy:cloudflare && npm run telegram:setup`. Автоматические preview-сборки отключены: отдельного preview-окружения Supabase/Telegram пока нет.

Сборка проверяет обязательные переменные и webhook secret, вызывает Telegram `getMe`, получает настоящее имя бота и передаёт его в конфигурацию Worker. Затем `db:check` проверяет все 22 таблицы, RLS и права RPC; при ошибке новая версия не публикуется. После успешного размещения настраиваются команды, меню Mini App и webhook. Платежи остаются выключенными.

Удалённая проверка из Cloudflare подтвердила бота **@Voklumi_bot**, действующий серверный ключ Supabase и схему **202611020008**. Для текущего приложения нужна **202611020010**. Последняя работающая версия сайта продолжает обслуживаться, пока preflight блокирует новую публикацию.

## Одно действие владельца в Supabase

Приложение использует Supabase Data API; серверный ключ не даёт права выполнять произвольные SQL-миграции. В этой задаче не настроены административный Management API token или доступ PostgreSQL. Не отправляйте их в чат.

1. Откройте нужный проект Supabase `wpctwlgfnkekgulgkxad`; проверьте резервную копию перед изменением схемы.
2. Откройте SQL Editor → New query.
3. Скопируйте **весь** файл [manual-upgrade-008-010.sql](../supabase/manual-upgrade-008-010.sql) и выполните от имени владельца БД.
4. Результат должен содержать `schemaVersion: 202611020010`, `ready: true` и 22 таблицы.
5. После этого повторите Cloudflare Build из панели либо отправьте следующий коммит в main.

Файл сгенерирован из исходных миграций 009/010. Обновление выполняется одной транзакцией с блокировкой, сохраняет учебный контент и историю миграций, поддерживает исходные версии 008/009. Повтор на 010 безопасен. Тест PGlite проверяет обновление, повтор, сохранение уроков и RLS/readiness. Файл не включает платежи и не назначает администраторов. Для регенерации: `npm run db:prepare-upgrade`; проверка: `npm run test:production`.

## Администратор и наблюдение

После настоящего Telegram-входа задайте `ADMIN_USER_IDS` как Build Secret: внутренний UUID своего профиля из таблицы users, не Telegram ID. Bootstrap перенесёт его в runtime; требуется новая сборка. Нельзя назначать первым администратором случайного пользователя. `SUPABASE_HEALTHCHECK_SECRET` — необязательный независимый секрет от 32 символов; такой же перенос открывает защищённый `/api/health/database` только для запросов с правильным bearer secret.

Главная, каталог и карта пока остаются демонстрационными экранами; это отдельная незавершённая интеграция интерфейса с базой. Полный Telegram-вход, прохождение и сохранение реального урока нужно проверить после обновления схемы. Не считать одну доступность `/api/health` доказательством готовности всех подключений.
