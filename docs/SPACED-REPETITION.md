# Этап E: интервальное повторение

Раздел `/review` доступен из профиля («Повторить слова»). После Telegram-входа показывает общее количество карточек, число доступных сейчас, английское слово и кнопку показа перевода. После попытки вспомнить пользователь выбирает «Не вспомнил», «С трудом», «Помню» или «Легко». Это самостоятельная оценка воспоминания, не автоматический языковой экзамен.

Слова берутся только из `lessons.lexicon` уроков с `user_progress.best_score >= 60`. Синхронизация происходит при открытии/обновлении очереди и после ответа, включая ранее пройденные уроки. Если старый урок не содержит словаря, система не придумывает изученные слова. Уникальность — пользователь + MD5 нормализованной пары en/ru; разные переводы сохраняются отдельными карточками. Первые текстовые снимки неизменяемы при повторной синхронизации, интервалы не сбрасываются. Возвращается до 20 доступных карточек; общее due учитывает всю очередь.

## Алгоритм

Документированный вариант SM-2: четыре оценки соответствуют q=0/3/4/5. При q<3 число последовательных успехов сбрасывается, следующий повтор через один день. При успехах интервалы: 1 день, 6 дней, затем round(предыдущий интервал × прежний ease), максимум 365 дней. После каждого ответа ease = max(1.3, ease + 0.1 - (5-q) × (0.08 + (5-q) × 0.02)); исходный ease=2.5. Поэтому три оценки «Легко» дают 1, 6, 16 дней. Расчёт выполняется PostgreSQL по серверному времени. Сохраняются число успешных ответов/ошибок, ease, интервал, серия успехов, последняя и следующая даты, версия.

Очередь может считать слово доступным сразу после успешного урока. Ошибка назначает повтор на завтра; внутрисессионного переобучения через минуты в этой версии нет. Постоянных фоновых задач, cron и платных API нет. XP за повторения не начисляется.

## Сохранение и безопасность

`POST /api/review` использует существующие Telegram HttpOnly-сессии, проверку Origin, лимит тела, whitelist полей и тайм-ауты RPC. user_id берётся из серверной сессии. `word_reviews` и `word_review_events` имеют RLS; PUBLIC/anon/authenticated не имеют прав на таблицы и RPC. Функции SECURITY INVOKER доступны только серверной service_role.

Ответ проверяет принадлежность карточки, due_at и version под блокировкой. Request UUID уникален для пользователя: повтор с теми же полями возвращает сохранённый результат; подмена полей, устаревшая версия и ранний повтор отклоняются. UI сохраняет request UUID при сетевой ошибке, защищён от двойного клика и сбрасывается при смене аккаунта. Клиентские поля интервала, времени и user_id не принимаются.

Миграция создана CLI и применена в Supabase как `20261103203004_spaced_repetition`; локальное имя приведено к зарегистрированной удалённой версии. Существующие уроки, попытки и XP не изменялись. Новые таблицы пусты до открытия очереди пользователем с пройденными уроками.

## Проверка

Worker build (Vite/vinext), ESLint и Prettier также пройдены. Удалённый вызов пустой очереди возвращает due=0; RPC закрыты для anon/authenticated. В адаптере остаются прежние предупреждения sourcemap и оптимизации импортов, сборка завершается успешно.

112 unit-тестов проходят, включая шесть новых SQL/PGlite-сценариев: отсутствие невыученных слов, дедупликация/повторная синхронизация, интервалы и идемпотентность, сброс после ошибки без XP, чужая карточка/невалидная оценка, запрет клиентских прав. TypeScript и production Next build прошли. Удалённый SQL подтвердил RLS и отсутствие клиентских прав.

Playwright и полноценная проверка на телефоне не выполнялись. Этап F (переработка карты и общей статистики) не начат. Публикация приложения — отдельный шаг: применённая миграция сама по себе не обновляет Worker.
