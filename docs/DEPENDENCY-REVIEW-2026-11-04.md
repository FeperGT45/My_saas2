# Разбор предупреждения minimatch

Проверено 4 ноября 2026 года на версии Voklumi `7bd013e`. Проверка физического телефона отложена по просьбе пользователя. Доступного устройства ADB не обнаружено; браузер компьютера и Android-эмулятор не считаются проверкой телефона.

## Результат

Полный `npm audit` сообщает о 16 пакетах с уровнем moderate. Это одна исходная проблема `minimatch`, распространённая по цепочке зависимостей ESLint, а не 16 независимых уязвимостей. Уровней high и critical нет. Повторный `npm audit --omit=dev` вернул 0 известных уязвимостей.

Предупреждение остаётся открытым. Изменения версий, подавление audit и принудительные overrides не выполнялись: совместимого исправления для используемых веток зависимостей не найдено. Для текущих вызовов Voklumi путь, описанный в advisory, не подтверждён как достижимый; это оценка ограниченного участка кода, а не гарантия отсутствия рисков.

## Что именно уязвимо

[GHSA-g3hv-75wg-m249 / CVE-2026-118764](https://github.com/advisories/GHSA-g3hv-75wg-m249) описывает увеличение расхода процессора и памяти при обработке специально подобранного glob-шаблона. В описанном случае `firstPhasePreProcess()` вызывается при `optimizationLevel >= 2`, а последующая обработка размноженных частей шаблона становится дорогой. Advisory указывает затронутый диапазон `<11.0.1` и исправление `11.0.1`.

Это проблема доступности инструмента, обрабатывающего шаблон; она не даёт сама по себе доступ к пользовательским данным, секретам или административным правам приложения.

## Что установлено в Voklumi

| Ветка                                         | Установлено        | Наблюдение                                                                                                                                                                                                                                   |
| --------------------------------------------- | ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ESLint и его плагины                          | `minimatch@3.1.5`  | Старый вызываемый CommonJS API и `makeRe()`. В установленном коде нет `firstPhasePreProcess` или `optimizationLevel`: конкретный механизм из advisory в этой ветке отсутствует, хотя audit помечает её по широкому диапазону версий.         |
| `@typescript-eslint/typescript-estree@8.72.1` | `minimatch@10.2.6` | Ветка содержит описанный механизм. Найденный вызов в `useProgramFromProjectService.js` передаёт только `{ dot: true }`; по коду minimatch уровень оптимизации по умолчанию равен 1. В конфигурации проекта `optimizationLevel: 2` не найден. |

`npm ls minimatch --all` показывает эту зависимость только в цепочке инструментов ESLint. Приложение не импортирует minimatch для обработки входных запросов. Отсутствие находок в production audit подтверждает отсутствие именно известных предупреждений в рабочей цепочке зависимостей, но не является полным аудитом безопасности приложения.

## Почему нельзя просто заменить всё на 11.0.1

[Changelog minimatch](https://github.com/isaacs/minimatch/blob/main/changelog.md) описывает несовместимые изменения: в 9.x исчез default export, а в 11.x удалены `makeRe()`, `Minimatch#regexp` и другие старые API. В установленном `eslint-plugin-import/lib/rules/no-internal-modules.js` есть вызов `minimatch.makeRe()`, а `@eslint/config-array` импортирует старый default export. Глобальный override на 11.0.1 ломает эти контракты и не является безопасным обновлением.

Проверка npm registry показала:

- последние доступные версии веток 3 и 10 — 3.1.5 и 10.2.6 соответственно; совместимый исправленный patch-релиз в этих ветках не найден;
- последняя версия `typescript-eslint` — 8.72.1, она уже установлена;
- даже `eslint@10.14.0`, актуальная версия из registry на момент проверки, объявляет зависимость `minimatch: ^10.2.6`. Переход только на ESLint 10 не закрывает эту находку и добавляет риск несовместимости.

## Решение для проекта

Сохранить предупреждение видимым и существующий lockfile. Обновить цепочку ESLint/плагинов, когда появятся совместимые версии, использующие исправленную реализацию или поддерживаемый backport. При таком обновлении проверять дерево minimatch, полный audit и запуск lint; при изменениях конфигурации также проверять TypeScript и сборку.

До обновления не добавлять в приложение обработку пользовательских glob-шаблонов через эту зависимость и не включать `optimizationLevel: 2` для непроверенных шаблонов. Текущая команда lint использует конфигурацию репозитория. Настройки безопасности и результаты audit не скрыты ради формально зелёного отчёта.

Команды для повторной проверки: `npm ls minimatch --all`, `npm audit`, `npm audit --omit=dev`, `npm view eslint@latest version dependencies --json`, `npm view typescript-eslint@latest version`.

В этой задаче менялась только документация. Проверки сборки и функциональности этапа G не повторялись: код приложения, конфигурация линтера и зависимости остались прежними.
