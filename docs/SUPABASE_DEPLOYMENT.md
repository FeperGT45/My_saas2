## Особенность сети Codex Cloud

В данном окружении используется Node.js 24 и исходящий HTTP/HTTPS-прокси. По умолчанию штатная Node-проверка не смогла подключиться; с **`NODE_USE_ENV_PROXY=1`** она завершилась успешно. Добавьте эту несекретную переменную в runtime окружения Codex при работе через настроенные `HTTP_PROXY`/`HTTPS_PROXY`. Не удаляйте proxy-переменные и не отключайте проверку TLS.

## Что остаётся конфигурацией окружения

URL и предоставленные API-ключи использовались для проверки в памяти процесса. Secret API key и Management access token **не записаны в файлы, Git или постоянные настройки Codex**. Для последующих запусков приложения задайте в настройках окружения:

- `NEXT_PUBLIC_SUPABASE_URL` — указанный выше публичный URL.
- `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` — проверенный публичный ключ проекта.
- `SUPABASE_SECRET_KEY` — серверный ключ через Secrets/runtime secret binding.
- `NODE_USE_ENV_PROXY=1` — при запуске Node.js 24 в данном проксируемом окружении.

Management token не нужен приложению в runtime; он нужен только для административного применения миграций. Не помещайте его в публичные переменные. Инструкция для Codex Cloud — в README. Чтобы проверить подключение после конфигурации, используйте `npm run db:check`.

Реальная авторизация в мобильном Telegram и production-развёртывание Mini App этой проверкой не подтверждаются. Для них по-прежнему нужны HTTPS-адрес приложения, runtime bot token и webhook. Дизайн приложения не изменялся.
